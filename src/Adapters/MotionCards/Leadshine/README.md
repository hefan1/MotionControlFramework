# 雷赛运动卡接入边界

当前目录中的 `MotionControl.VendorApi.Leadshine` 只保存 `LTDMC` 原生 API 声明。这里还没有可供 Host 选择的雷赛运动卡适配器，也没有雷赛仿真器或实体卡验证结果。

## 参考工程结论

- `Leadshine.CNC.POL_V2.2.05-20210929` 为 DMC5610 和 DMC5410 分别建立卡/运动对象，并分别维护运动参数集合。它说明同一厂商的不同卡型也可能需要不同的配置和实现。
- `版本库_202400613-V1.0.1.7_修改真空检测_恢复版` 中的 `PrimLESI` 调用 `LTDMC.dmc_*` 完成定位、停止和回零参数设置，并在运动调用前把工程距离、速度换算到脉冲量。该工程还包含其他控制卡实现，不能把其中一个实现当作所有雷赛卡型的统一方式。
- 两个参考工程都可以帮助理解雷赛脉冲卡 API，但不能据此推断某个未确认型号的总线卡使用相同 SDK、回零语义或报警处理方式。

## 新适配器应负责的内容

1. 在 `VendorApi` 层保留厂商 DLL 声明和原始返回码。
2. 在具体 `Adapter` 层实现框架的 `IMotionCard`、`IAxis` 与逻辑 IO 契约。
3. 在适配器配置中保存物理轴/IO 通道、工程单位换算、回零模式、信号极性和该型号独有参数。
4. 把厂商轴状态、停止原因、报警码和错误码映射为框架约定的状态，同时保留原始诊断信息。
5. 按目标型号逐项完成适配器验收清单；未验证的能力明确标记，不根据 DLL 声明推断为可用。

若后续型号使用不同 SDK 或不同的总线初始化/状态语义，应建立独立的适配器实现；只有确认共用的 SDK 行为一致后，才复用同一个适配器。
