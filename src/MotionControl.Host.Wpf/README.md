# Host WPF

Host 是设备上位机的组合入口：它创建当前设备配置、通用页面、运行时和本次运行选择的运动卡连接实现。

## 隔离配置调试

开发调试可传入 `--simulation-config-root <本机绝对目录>`，让同一个 Host 把设备配置和恢复文件放在指定目录，并在窗口标题和顶部显示“隔离测试配置”。该目录不能是磁盘根目录、目录联接，也不能与正常配置根目录相同或互相包含；参数错误时直接停止启动。此入口与正常 Host 共用单实例锁，不能同时控制同一张卡。未传该参数时仍使用正常配置目录。

隔离的是配置文件，不是控制器或硬件安全回路；启动后仍按配置连接当前适配器，因此在连接或操作前必须确认控制器身份、轴和 IO 状态。目前 Host 的正运动适配器只允许本机 `VPLC5xx-Simu`。该入口不改变实际卡型的支持范围。

“首页 → 设备总览”和“报警 → 当前报警”已接入当前传统 Runtime。任务配置与列表编辑沿用“设置 → 任务配置”。独立四页预览参数 `--ui-workspace-preview` 在创建控制卡和现场恢复服务之前返回，使用独立配置目录。页面职责、数据边界和代码位置见 [Operation/README.md](Operation/README.md)。

“监控 → 设备变量”显示本机变量表。首次启动时 Host 从当前设备项目的 `EquipmentTemplates/Parameters/DeviceVariables.json` 复制默认变量；之后只读写本机 `%LOCALAPPDATA%/MotionControlFramework/Configurations/<MachineId>/Parameters/DeviceVariables.json`，不会覆盖已存在的现场配置。变量运行值在内存中供设备流程和监控页共用。

Host 在工位受控暂停后保存设备变量值、可恢复工位步骤和初始化完成标记到本机 `%LOCALAPPDATA%/MotionControlFramework/Configurations/<MachineId>/Runtime/RecoverySnapshot.json`。关闭时尝试自动停止任务及工位并等待收尾，随后核查控制卡断连及输出保持条件；停止、状态读取或控制器断连行为不确定时保留窗口并提示原因。重启后连接卡，确认恢复提示，再按设备要求处理现场、复位和启动；不会自动发运动或输出命令。流程断点只在设备配置一致且工位显式实现 `IRecoverableStationFlow` 时续跑。新增、删除或改类型的变量按名称和 .NET 类型逐项校验；不匹配的变量使用当前配置初值，并阻止旧流程自动续跑。

上述保存有明确边界：任务会话仍持有控制权、资源待确认或设备状态尚未结算时，不会覆盖原快照，也不保证该快照包含最后一次生产状态。持久资源记录及控制器断连能力均确认后，任务可保留隔离记录并交接退出；无法确认时仍保留窗口及控制权。重启后不得删除标记、假定旧快照就是最新现场或自动继续旧任务。当前版本尚不能对这些跨锁状态提供一致的停机现场快照。

断连前要求适配器明确声明断开会话后的输出保持行为，并两次核对已映射输出；当前只有本机软件控制器实现该声明，正运动等真实卡尚未验证，因此连接状态下关闭会保守拒绝。此声明也不能证明未映射物理输出或软件控制器进程停止后的状态。

## 设备工程导入和导出

在“设置 → 设备工程”可导出当前设备工程、选择工程并逐文件对照预览、应用导入，以及查看导入前备份。工程包含已登记的设备配置和任务，不包含 `Runtime` 运行/恢复记录、`Drafts` 草稿或 `Backups`；包外文件保留。导入前必须结束设备动作和任务、断开控制器、解决未确认恢复状态并保存正在编辑的内容；成功后关闭并重新打开 Host，重新连接和准备设备。

设备专用参数须按 [工程配置说明](../MotionControl.TaskEngine/Configuration/README.md) 在可信静态清单登记；未登记参数会阻止导出完整包并列出文件。工程包不会安装 C# 设备代码，也不会验证真实接线或机械安全；应在目标设备核对卡型、轴行程、IO 极性及安全配置。中断应用会在 Host 加载设备配置之前尝试从本次备份恢复；恢复证据不可信或文件被其他程序更改时，保留标记并阻止连接。

任务列表的“保存记录”步骤将同一变量快照写入 `Runtime/TaskRecords`；双夹位 C# 示例的现场证据和已出料记录分别写入 `Runtime/Evidence`、`Runtime/EquipmentRecords`。任务运行页的“产品记录”提供只读查询。记录时间是软件写入的时间，扫码模拟设备的编号也只保证本次控制器会话内唯一，均不能代替真实设备的追溯系统。物理出料后如果记录写入失败，必须人工核对产品去向，软件不会撤销已发生的动作。

启动初始化默认在新连接后重新执行。设备流程如要在软件重启后避免重复回零，必须显式实现 `IRecoverableEquipmentInitializationFlow`；Runtime 会在启动时调用 `CanSkipAfterRestartAsync`，由设备流程读取当前轴、传感器和工艺状态。只有该实时检查确认安全，且 Runtime 再次确认轴已停稳、无报警/限位并满足回零要求，才跳过初始化；检查返回 false 时完整执行原初始化，检查异常时禁止启动。恢复文件本身不会把轴标记为已回零。配置发生变化、变量定义不匹配或暂停发生在初始化中时，不允许使用旧初始化完成标记。

## 运动卡连接位置

- `App.xaml.cs` 的 `CreateMotionCardConnection()` 委托 `HostMotionCardBackendSelection` 选择控制器后端。设备流程和通用页面不在这里选择厂商。
- `IMotionCardHostConnection` 给 Host 提供通用的 `IMotionCard`、`ILogicalIo` 和已加载硬件映射。Host 运行逻辑通过这些契约创建运行时及手动调试页。
- `VirtualAxisMappingCardConnection` 把已保存的轴与 IO 映射交给本机软件控制卡适配器；控制器是独立进程，协议与操作命令见 [本机虚拟控制器说明](../../tools/MotionControl.VirtualController/README.md)。该路径不调用正运动 SDK。
- “IO 监控”页由 Host 组合根注入当前连接、IO 能力范围、物理通道监控可选接口和 DI/DO 映射；页面本身不连接或重连控制卡。
- `ZMotionAxisMappingCardConnection` 是当前正运动仿真器的 Host 接入实现，负责读取设备配置、建立 ZMotion 适配器并提供轴映射页需要的参数读写。
- 轴映射页使用 `IAxisMappingCardConnection`；可读取卡上 IO 能力时，由连接实现另外提供 `IMotionCardIoCapabilityProvider`。适配器还可以单独实现 `IAxisMappingCardOnlineApply`，在卡型、连接资料和物理轴集合未变化时保留卡连接并在线应用轴映射；其他情况由页面提示后走重连路径。
- 当前正运动适配器支持相同物理轴集合的在线更新。参数确有变化时先确认已映射轴全部停止，再通过正运动 API 更新需要改变的参数，并复用现有轴对象；如果只改显示名称等运行时映射资料，不会重复写卡参数。新增或移除物理轴仍需重连，重连会清除回零完成状态。
- 正运动连接的 IO 映射保存会检查轴已停止后，在当前卡实例内替换 DI/DO 逻辑映射，不重连控制卡。软件控制器当前不支持映射在线修改，轴映射页为只读、IO 映射页不支持保存；两者都读取既有设备配置。

### 选择本机软件控制器

在 `%LOCALAPPDATA%/MotionControlFramework/Configurations/Machine01/Parameters/ControllerBackend.json` 中写入以下工程配置后，启动独立控制器，再启动正式 Host；没有此文件时默认使用原有正运动连接。端口只能用于本机，必须与独立进程一致。

```json
{ "backend": "Virtual", "port": 18520 }
```

当前电脑保留 `Virtual` 配置；切回正运动需要明确将 `backend` 改为 `ZMotion` 并重启 Host。未知后端和连接失败均报错，不会自动换到其他后端，也不会改写 `MotionCards.json`。顶部状态栏应以实际页面状态为准，底栏通过“软件控制器 已连接/未连接”区分连接身份。

软件控制器和 Host 采用独占租约与心跳：租约超时后由控制器侧停止软件轴，但**不会自动更改输出**。Host 检测到通信中断后显示未连接，旧轴和输出状态视为未确认，旧运行时保留供检查并阻止原地重新接管；检查并结束运行后重新启动 Host。控制器进程重启会丢失轴、IO 和供料状态，需要重新检查伺服、回零并启用上料规则。此保护不代替现场急停和真实设备安全回路。

## 单工位流程核对

- Host 的启动、暂停、停止使用同一个 `MachineRuntime` 并与手动页共享控制卡及逻辑映射。暂停保留当前工步；停止会等待动作收尾、核查轴和资源，并显示“已停止”。停止后原任务会话、工步及输出仍保留，继续旧工步须在顶部报警复位时明确确认，复位后仍需主动启动。停止不自动清料或重建工艺起点，具体处理由设备项目定义。任务页的“停止并关闭任务”是会话终止，可能留下待核查资源，与顶部停止生产不同。
- 示例设备优先读取当前设备目录的 `Parameters/DemoStations.json`，为每个启用项创建 `DemoStationFlow`；没有工位清单时兼容旧版 `Parameters/DemoStation.json`。未启用工位时不会创建自动工位，配置错误时会报告具体原因。配置字段和流程顺序见 [示例工位说明](../MotionControl.Equipment.Demo/README.md)。
- 当前示例工位明确保存 10、20、30、40 步编号；暂停后重启会从保存步骤起点执行。若暂停发生在有外部副作用的步骤中，设备项目必须确认该步骤可以安全重试，或在流程中补充可恢复的工艺状态判断。
- `Parameters/Equipment.json` 的 `executionOwner` 使用 `StationFlows` 选择 C# 工位、`TaskEngine` 选择任务列表；两条路径不能同时控制设备。当前 Machine01 保留 `StationFlows`。任务列表通过“监控 → 任务接入状态”装载和启停，C# 工位使用顶部整机按钮。任务列表在 DO 打开后的保持步骤暂停时，实测输出保持当时状态；是否释放需要遵照设备工艺，不能假设暂停会自动关闭。
- 在“监控 → 流程状态”查看整机状态、当前步骤、超时报警和最近故障。操作顺序为连接控制卡 → 整机复位 → 启动 → 观察轴定位与 DI → 观察 DO 脉冲；保持 DI 无效可核对超时报警，再复位重试。

协议 2 软件控制器下，正式 Host 已屏幕验证上料工位两种流程的循环、暂停、缺料报警与恢复，以及 C# 流程断线状态。上述仅为软件控制器验证，不证明正运动 SDK 或实体设备已验收。

## 增加另一种控制卡

为新卡型建立对应的 VendorApi 与驱动适配器，在 Host 中实现 `IMotionCardHostConnection`，提供该卡型选项、配置转换和逻辑 IO。随后在 `CreateMotionCardConnection()` 选择新的实现，并更新 Host 的项目引用、设备硬件配置和匹配的原生运行库。

设备流程继续使用逻辑轴、逻辑 IO 和工程单位。新适配器需要按目标卡型和 SDK 版本单独验证；API 声明或其他卡型的仿真结果不能代替验证。

当前 Host 可选择一张正运动 `VPLC5xx-Simu` 或本机软件控制器。Runtime 的 `MotionCardGroup` 虽然可以管理多张卡，但当前 Host 连接接口和轴/IO 配置页只接入一张卡；连接时发现 `MotionCards.json` 配置多张卡会明确拒绝，避免只连接第一张卡而遗漏其余卡。正运动适配器当前不支持实体卡；雷赛、固高、ADLINK 等目录中的原生 API 声明不代表已有可运行的驱动适配器。
