# 夹具焊接线 C# 测试流程

本例参考夹具焊接项目的扫码、焊接、压合、复检和载具流转，使用四个独立工位和四个单件载具位；下一工位占用时当前工位等待，其他工位仍可运行。编号由测试程序生成，不连接扫码枪、视觉、焊机或复检设备，也不代表真实产品追溯或检测结果。各站输出和反馈仅为测试时序，不能照搬参考设备的接线及安全逻辑。

此代码流程只允许 `Parameters/ControllerBackend.json` 明确配置 `Virtual` 时创建，不适用于实体设备。每次重新创建设备流程会清空内存载具，不能用于断电后产品恢复；确认无在制品后才能启动新的测试会话。暂停或报警保留当前会话内的步骤及载具，输出保持执行时的状态，不能假设暂停自动关闭夹具或其他输出。

## 配置和信号

`Equipment.WeldingExample.json` 是运行入口示例；先安全关闭 Host，备份 Machine01 现有 `Parameters/Equipment.json`，核对下面的映射后再将示例内容安装为该文件。测试完成后按项目规则保留当前测试配置，备份仅用于用户明确要求的恢复。现有任务清单、任务草稿和原 C# 示例工位文件不需要覆盖。

| 测试工位 | 逻辑轴 | 逻辑 DI / 通道 | 逻辑 DO / 通道 | 控制器测试规则 |
| --- | --- | --- | --- | --- |
| 扫码 | Load_X | 上料到位 / DI4 | 夹具夹紧 / DO0 | 上料规则，首次 1000 ms、后续 1500 ms |
| 焊接 | Press_Z | 压装完成 / DI5 | 压头动作 / DO1 | DO1 → DI5，300 ms |
| 压合 | Camera_X | 检测完成 / DI6 | 相机触发 / DO2 | DO2 → DI6，300 ms |
| 复检 | Unload_X | 下料到位 / DI7 | 下料电磁阀 / DO3 | DO3 → DI7，300 ms |

这些名称沿用 Machine01 已有映射，工位名称与 IO 名称不代表实体设备信号对应关系。四轴各在 0 和 1 工程单位之间以 5 单位/秒运动；创建工位时检查轴映射及 0 到 1 是否在配置行程内。焊接、压合及复检工位在运动前和到达工作位后分别等待完成反馈复位，避免把旧有效信号当成本次完成。普通软件读取与输出并非原子操作，这些检查不能代替现场联锁。输入输出都按已有映射的逻辑有效电平操作，软件控制器配套规则要求表中通道为高有效。`DEMO_SENSOR_TIMEOUT` 必须在报警库中存在且为停机报警。

## 正式 Host 检查

1. 核对后端为 Virtual、上表轴与 IO 映射、无旧 Host 会话、相关输出关闭；以正式 Release Host 和本项目软件控制器测试。可用 `tools/MotionControl.VirtualController/StartLoadDemo.ps1` 启动软件控制器、DI4/DO0 上料规则和正式 Host；该脚本只校验上料映射，不校验其余三组反馈映射。
2. 在 Host 的 IO 页面核对状态，并按上表确认后分别使用 `ControllerCommand.ps1 -Action ConfigureFeedback -OutputChannel 1 -InputChannel 5`、`-OutputChannel 2 -InputChannel 6`、`-OutputChannel 3 -InputChannel 7` 建立其余三组测试反馈；完成后复核相关输入与输出。避免覆盖已有测试规则。
3. 在 Host 检查四轴伺服、回零和行程，按实际测试步骤复位、启动；在“流程状态”观察四站当前步骤和各自测试产品/载具编号。`DI7` 反馈保持无效可模拟复检等待，上游会逐站等待下游空位；恢复反馈后继续流转。
4. 暂停、故障或退出前先观察轴和输出；结束时在 Host 停止流程、确认轴停止并按测试场景关闭仍有效输出，再停止上料规则、移除三项反馈并复核 DI 安全值。不得用该过程代替实体设备的安全回路和现场工艺验证。

内部检查：`dotnet run --project tools/MotionControl.WeldingExample.Checks -c Release`；其受控假设备检查并行、堵塞、暂停恢复和旧反馈有效时禁止运动及输出，不代表正式 Host 屏幕或控制器验证。
