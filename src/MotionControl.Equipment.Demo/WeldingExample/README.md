# 夹具焊接线 C# 测试流程

本例参考夹具焊接项目的上料、焊接、压合、复检下料和载具流转，使用四个独立工位和四个单件载具位；下一工位占用时当前工位等待，其他工位仍可运行。编号由测试程序生成，不连接扫码枪、视觉、焊机或复检设备；结果来自软件控制器的测试反馈，不代表真实产品追溯或检测结果。各站输出和反馈仅为测试时序，不能照搬参考设备的接线及安全逻辑。

此代码流程只允许 `Parameters/ControllerBackend.json` 明确配置 `Virtual` 时创建，不适用于实体设备。每次重新创建设备流程会清空内存载具，不能用于断电后产品恢复；确认无在制品后才能启动新的测试会话。暂停或报警保留当前会话内的步骤及载具，输出保持执行时的状态，不能假设暂停自动关闭夹具或其他输出。

## 配置和信号

`Equipment.WeldingExample.json` 是运行入口示例；先安全关闭 Host，备份 Machine01 现有 `Parameters/Equipment.json`，核对下面的映射后再将示例内容安装为该文件。测试完成后按项目规则保留当前测试配置，备份仅用于用户明确要求的恢复。现有任务清单、任务草稿和原 C# 示例工位文件不需要覆盖。

| 测试工位 | 逻辑轴 | 逻辑输入 | 逻辑输出 |
| --- | --- | --- | --- |
| 上料 | Load_X | 上料到位、夹具夹紧到位、夹具松开到位 | 夹具夹紧 |
| 焊接 | Weld_Z | 焊接完成 | 焊接启动 |
| 压合 | Press_Z | 压装完成 | 压头动作 |
| 复检下料 | Camera_X、Unload_X | 相机触发反馈、检测完成、检测OK、检测NG、下料到位 | 相机触发、相机结果复位、下料电磁阀 |

逻辑名称由设备配置映射，不能假定 DI 和 DO 同号即自动联动。五轴各在 0 和 1 工程单位之间以 5 单位/秒运动；创建工位时检查轴映射及 0 到 1 是否在配置行程内。焊接、压合及复检工位在运动前和到达工作位后分别等待完成反馈复位。夹具夹紧和松开到位同时有效、相机 OK 和 NG 同时有效时流程报错，不会继续下料。相机依次等待触发反馈、检测完成和唯一结果，再发出结果复位并等待清除；OK 和 NG 只是记录结果，当前下料动作不区分分拣去向。普通软件读取与输出并非原子操作，这些检查不能代替现场联锁。`DEMO_SENSOR_TIMEOUT` 必须在报警库中存在且为停机报警。

## 正式 Host 检查

设备配置齐全且无旧 Host 时，可运行 `powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\MotionControl.VirtualController\StartClipWelding.ps1` 启动本项目软件控制器和正式 Host。脚本按名称读取实际映射，配置夹具、焊接、压装、相机与下料模型；不会使能、回零或启动任务，也不会自动启用供料。完成设备准备后，按脚本打印的实际通道执行供料命令；其中上料轴安全位门禁避免轴离开安全位时提前计时供料，但不能识别 Host 暂停或载具交接，也不是实体设备安全联锁。`-ConfigurationRoot <隔离目录> -PrepareOnly` 可用于独立模型准备检查，不启动 Host。

1. 核对后端为 Virtual，配置五轴和上表全部逻辑信号；旧四轴测试配置缺少 Weld_Z 和独立反馈，不可直接使用新版 C# 流程。按实际测试映射配置供料、夹具、焊接、压装、相机和下料模型，不能用单纯 DO 跟随伪装相机完成和结果。
2. 在 Host 核对轴、IO 和相关输出，准备期间停止供料并确认上料位置无料。先在轴手动页完成 Load_X、Camera_X、Unload_X 的使能和回零；再在“设备准备”完成 Weld_Z、Press_Z 两个工位回零并核对待机位置。手动轴或 IO 操作会使已完成的准备资格失效，应在设备准备之前处理。
3. 开启供料，复位并启动；在“流程状态”观察四站步骤、载具编号和相机测试结果。暂停、故障或退出前先观察轴和输出；结束时通过 Host 停止流程，确认轴停止，按测试场景处理仍有效输出，停止规则并复核 DI 安全值。不得用该过程代替实体设备验收。

相机等待检测完成或有效结果超时后，排除故障并在 Host 报警复位、启动；代码样例会先复位相机的旧处理及结果，再重新触发本载具的检测。普通暂停不触发这项重试，保留当前步骤和输出。以上是本软件测试模型的恢复方案，不代替实际相机协议及设备工艺确认。

内部检查：`dotnet run --project tools/MotionControl.WeldingExample.Checks -c Release`；其受控假设备检查并行、堵塞、暂停恢复、旧反馈拦截及设备准备，不代表正式 Host 屏幕或控制器验证。

## 工位准备代码定位

- `WeldingExampleEquipmentDefinition.CreatePreparations` 通过框架的可选 `IEquipmentPreparationProvider` 提供两个准备流程。框架不知道焊接、压合的名称、轴和 IO；依赖关系也保留在此设备项目。
- `WeldingStationPreparation` 是本测试设备的具体顺序：只读前置检查 → 连续 1.5 秒反馈复位确认 → 轴使能 → 按适配器参数回零 → 返回 0 mm 待机位 → 实时验收。压合依赖焊接准备完成，并在动作前再次读取焊接轴的停稳、坐标参考、0 mm 位置及对应 IO。
- `WeldingCarrierLine` 记录当前会话是否执行过生产及载具占用。准备不能清空此状态；生产执行过即拒绝重新准备，避免把暂停现场当作空机。本例不支持带料回零或断电在制品恢复。

准备开始要求 DI4 无料、对应动作 DO 关闭、完成 DI 无效、轴停稳无报警且硬限位可确认；不会擅自关闭夹具输出来制造条件。准备后可正常供料，最终就绪检查不要求 DI4 无效。IO 读取错误直接报告；输入/输出检查与运动命令不是原子安全联锁，不能替代真实机构的安全功能。

单次准备最长 20 秒；失败或取消均请求相关轴受控停止并确认，准备保持未完成。失败原因处理后可重试；每次重试从前置检查开始，不能把中断回零当作已完成。停止失败同时保留原始故障和停止错误，不伪报停稳。准备成功只代表这两个测试模组满足规定条件，不自动启动生产，也不代表其他工位已经准备好。

维护其他设备时，应在该设备项目编写对应的 `IStationPreparation`，使用逻辑轴/IO 和明确步骤。不要把本示例的 0 mm、1.5 秒、工位依赖或输出处理方式搬入通用 Runtime。
