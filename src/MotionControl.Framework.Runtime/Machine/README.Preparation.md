# 通用设备准备与工位回零

`MachineRuntime.Preparation.cs` 只负责准备流程的依赖顺序、独占操作、状态、停止与生产启动资格。它不包含焊接、压合或任何设备专用轴和 IO 名称。

## 设备与执行方式

- C# 设备定义可实现 `IEquipmentPreparationProvider`，通过已有设备环境和生产工位创建 `IStationPreparation`。具体回零顺序、气缸/夹具条件和工艺限制都放在设备项目。
- 任务列表由任务适配器把独立的准备任务转换为同一 `IStationPreparation`。准备与生产复用同一个设备会话，不能另建控制器会话抢占命令权。
- Host 安装当前入口的准备项，用同一页面显示 `PreparationStations`，调用 `PrepareAsync` 和 `StopPreparationAsync`。更换设备只更换准备项，页面不编排设备动作。
- `ConfigurePreparations` 只允许空闲时调用，更换后资格全部失效。关闭任务会话并切回 C# 时，应恢复 C# 原始准备项，不能清空列表绕过准备闸门。

## 运行语义

`PrepareAsync(null, token)` 按依赖顺序准备全部工位；传入工位标识时自动包含其前置工位。已有完成资格的前置工位会实时检查姿态，检查通过时不重复执行。所有所选工位的只读 `ValidateStartAsync` 都先通过，才执行任何准备动作；每个工位动作后还要通过 `ValidateReadyAsync` 和轴停稳核对。

操作允许从待复位、就绪或暂停进入，但急停必须已配置且无效、轴必须停止且无报警、停机报警必须已复位。准备过程中禁止手动动作、生产启动、报警复位、断开和任务入口切换；急停与现场停止按钮仍有效。

准备成功只回到 `Ready`，不会自动生产。C# `StartAsync` 与任务 `BeginTaskEngineRunAsync` 都检查准备资格，首次生产启动还验收当前初始姿态。任务 Host 必须在 `TaskMachineController.Start()` 成功后调用 `ConfirmTaskEngineProductionStarted()`，不能把仅打开运行保护误记为生产已开始。

正常生产暂停/报警复位保留准备资格和工步，续跑不要求回到开机位置。生产已经开始后，重新准备会被拒绝且不破坏原资格。普通手动轴/IO操作撤销准备资格，但保留“本会话已生产”的历史；此时不能重回零后继续旧工步，应结束当前生产会话并核对在制品，再建立新上下文。设备准备项仍须独立检查在制品和保留工步，不能清空载具数据制造准备完成。

准备取消时受控停止并回到待复位，失败时锁存 `PREPARATION_FAILED`，具体步骤和原因在准备页面保留。任何停稳读取失败或停止超时都保留准备占用；只能继续停止确认，不允许清报警或插入动作。再次确认停止成功后才解除该占用。准备资格不持久化为硬件事实，断开/重连会失效。

## 维护与检查

维护工艺请修改设备准备项或任务文件；维护独占/取消/资格请修改 Runtime 准备文件；维护显示请修改 Host 设备准备页。厂商回零模式、有效电平与运动结果仍由 `IAxis` 对应适配器实现。

`tools/MotionControl.Preparation.Checks` 使用内存替身验证依赖、独立准备、两入口启动闸门、暂停续跑、手动失效、停止、急停、未知状态及失败恢复边界。它不替代正式 Host 屏幕验证，也不证明实际机械的让位、夹持或安全回路。
