# 13 轴双夹位任务列表示例

本目录是设备工艺示例，不能当作真实设备接线图、安全逻辑或工艺参数。流程分别由上料与转台、焊接、压合、复检分拣四个循环工位执行；同一夹位必须先完成焊接，再转至压合位。A/B 夹位在 `Conveyor_R` 的 -90° 和 +90° 之间交换，焊接位与压合位使用不同的命名资源，可并行加工。相机与下料机构使用独立缓存资源，缓存占用时上游等待。

本样例通过软件控制器的独立扫码设备输入读取 16 位编号；扫码完成、成功及数据有效后才产生产品标识。编号仅在该软件控制器运行期间唯一，控制器重启后不保证跨会话唯一，不等同真实扫码设备或产品追溯系统。所有伺服轴及逻辑 IO 使用设备配置中的名称；同号输入和输出没有自动联动。

## 文件职责

- `RotaryPrepare.json`：确认测试区域无料、输出关闭、夹具松开后，先回零竖直轴，再回零水平轴和转台，最后将转台移到 -90°。此流程不会自动使能伺服。
- `RotaryInit.json`：检查上料、焊接、压合和缓存的占料记录均为无料，检查转台当前位置；不会清除占料记录。
- `RotaryTable.json`：取料、扫码、放料、两工位请求与等待、下料以及转台交换。`Rotary.WeldIsA` 记录当前焊接位置对应的夹位。
- `RotaryWeld.json` 和 `RotaryPress.json`：分别在各自资源范围内执行焊接或压合，结束时确认加工轴返回安全位。
- `RotaryInspect.json`：缓存定位、相机检测、按结果送往 OK/NG 出口；NG 产品还需执行剔除并确认反馈。
- `TaskMachine.json`、`StationPreparation.json` 和 `Variables.additions.json`：分别定义设备工位、设备准备和本样例独立设备变量。

流程使用 `WaitAxisPosition` 检查轴处于已使能、已回零、停止、无报警且在预期位置；`ReadInputWord` 按低位在前读取 `扫码数据00` 至 `扫码数据15`。资源范围内异常时资源保留待确认；这些动作前检查不是连续安全监控，不能替代机械安全回路。任务设备不支持的轴组运动没有退化为假并行；不同工位按实际单轴动作并行。

## 产品记录

复检分拣工位在出料动作前写入“待出料”记录，出料反馈确认后写入“已出料”记录；每条记录使用同一设备变量快照，包含产品编号、A/B 夹位、工位、阶段、检测结果和出口。两次写入都成功后才清除缓存占料。正式任务设备将记录单独写入设备目录下 `Runtime/TaskRecords`，不覆盖已有文件；记录写失败或值未知时，任务停止并保留待确认区域。若设备实际出料后记录写入失败，需要现场核对，软件不能撤销已完成的物理动作。

编辑任务时可新增“保存记录”步骤，填写记录类别，并按“字段名 = 字符串变量名”逐行维护；检查任务时会校验变量引用，执行详情显示保存时的字段和值。文件记录不自动提供跨会话产品唯一性、数据库检索或现场产品追溯；软件扫码重启后可能重复，使用真实设备前应接入实际扫码与追溯服务。

## 本机验证

只对独立测试配置进行安装与测试，配置必须包含 13 根对应逻辑轴、所需 IO、`DEMO_SENSOR_TIMEOUT` 和 `FOUR_HANDSHAKE_TIMEOUT` 停机报警，并启用任务列表入口。先关闭上位机、备份已有设备配置及草稿；不要覆盖或删除运行恢复记录。使用项目的软件控制器准备脚本创建隔离配置后，在正式 Release Host 核对连接及 13 轴状态、完成伺服使能和设备准备，再独立启动生产。结束后停止供料，确认所有轴停止、测试输出关闭并检查相关输入。

暂停或同会话报警后，工位和占料变量应保留；重启、占料不明、读取失败或资源待确认时，不得通过清空变量、删除恢复文件或仅修改步骤来强行续跑。异常后是否能安全继续须在正式 Host 和具体设备条件下分别验证。
