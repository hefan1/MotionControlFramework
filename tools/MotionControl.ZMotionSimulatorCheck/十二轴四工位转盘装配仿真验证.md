# 十二轴四工位转盘装配仿真验证

## 验证结论

本次在 ZDevelop 所连接的 `VPLC5xx-Simu` 仿真控制器上完成了十二轴、六个并行工位流程的实卡 SDK 仿真验证。运行、暂停、共享轴排队、良品/不良品分流和三轮节拍全部通过；验证程序结束时，十二根轴均恢复到本次运行前的位置并确认停稳。

本次没有写入 DO；ZSimu 的虚拟 DI 全程保持关闭。ZSimu 中勾选的 DO2 是输出监视项，本次没有通过程序或界面切换输出。

这是仿真控制器验证，不代表真实控制卡、伺服、电气接线、机械碰撞边界或整机安全已经验收。

## 场景与轴分工

场景模拟一台转盘式上料、压装、视觉检测、下料设备。六个流程各自执行明确工艺动作，并通过共享状态完成工位交接。

| 物理轴 | 测试逻辑名称 | 模拟用途 |
| --- | --- | --- |
| 0 | `Dial_Index_R` | 转盘分度 |
| 1 | `Load_X` | 上料横移 |
| 2 | `Load_Z` | 上料升降 |
| 3 | `Press_Position_X` | 压装定位 |
| 4 | `Press_Head_Z` | 压头升降 |
| 5 | `Vision_X` | 视觉横移 X |
| 6 | `Vision_Y` | 视觉横移 Y |
| 7 | `Vision_Z` | 检测升降 |
| 8 | `Unload_X` | 下料横移 |
| 9 | `Unload_Z` | 下料升降 |
| 10 | `Shared_Transfer_X` | 上料与下料共用的转运轴 |
| 11 | `Feeder_Pusher` | 伺服送料推杆 |

流程由六个独立工位组成：转盘、上料、伺服压装、视觉检测、良品/不良品出料和送料。`Shared_Transfer_X` 被上料与出料两个工位共同申请；转盘必须等五个工艺工位都完成并退回等待位后才可分度。

测试使用仿真轴配置 `UNITS=1000` 脉冲/工程单位。正运动 PC 函数库手册说明 `UNITS` 表示每个工程单位对应的脉冲数，详见[正运动 PC 函数库编程手册 V2.1.2](https://www.zmotion.com.cn/upload/ZMotion%20PC%E5%87%BD%E6%95%B0%E5%BA%93%E7%BC%96%E7%A8%8BV2.1.2.pdf)。这组单位换算仅用于本次仿真场景，不是任何实际设备的轴参数建议。

## 验证过程与结果

1. **连接前检查**：ZDevelop 画面显示已连接 `VPLC5xx-Simu Version:4.99-20180521`；ZSimu 显示仿真电源开启，输入 DI 0–23 均关闭。程序逐轴读取 0–11，确认无运动、无报警且未触及软硬限位，然后才继续。
2. **首轮并行与整机暂停**：观察到最多 7 根轴同时运动后触发整机暂停；暂停后所有轴停止，已申请的共享轴资源清零。
3. **争用期间暂停**：实际观察到出料工位持有共享转运轴、上料工位等待同一逻辑轴。随后暂停整机，轴停止且共享占用清零。
4. **完整生产循环**：完成三轮工位加工和两次转盘分度；完整循环的同时运动峰值为 6 根轴。上料累计等待共享轴 27,116 ms，出料累计等待 13,509 ms；这是本轮三周期的排队累计时间，不代表单次请求的延迟。
5. **条件分支**：视觉模拟结果触发两次良品路径和一次不良品路径，结果为良品 2 件、不良品 1 件。
6. **结束与恢复**：十二轴全部返回各自测试起始位置并确认停稳。结束画面中，ZDevelop 仍显示 `VPLC5xx-Simu` 已连接；可见轴 0–4 的 DPOS/MPOS 与测试前基准一致，状态位为停止。ZSimu 的虚拟 DI 仍全部关闭，DO2 仍只是输出监视勾选项。

## 这次验证覆盖的能力

- 多个工位各自持有自己的轴组，并在运行时并行推进。
- 一个流程步骤可以同时发起多轴动作，并等待动作全部结束。
- 工位通过送料到位、工位完成、视觉结果等条件进行握手。
- 良品和不良品走不同的设备步骤。
- 两个工位争用同一根逻辑轴时，资源协调器让其中一个等待；最大同时持有者为 1。
- 整机暂停能停止当时正在运行的仿真轴，并释放共享轴资源。
- 三轮流程完成后，所有轴都能回到验证前位置。
- ZMotion 单脉冲量化造成命令位置偏差时，到位判断同时参考轴配置容差和脉冲分辨率；实际反馈仍需落在配置容差内。本次曾观察到 0.001 工程单位的单脉冲差值，使用配置容差后定位通过。

## 尚未覆盖的边界

- 本测试的工位握手、良品/不良品结果由仿真流程状态模拟，没有接现场 DI、相机、压装控制器、MES 或 PLC。
- 逻辑轴资源协调只保护同一逻辑轴不被两个流程同时驱动，不会自动判断不同物理轴之间是否存在机械碰撞。
- 运动目标按仿真配置软限位检查；没有真实机械尺寸、零点、工装和安全距离，因此不能证明物理避让安全。
- 本次没有切换仿真输入，也没有执行 DO 写入、伺服使能或实体设备动作。
- 其他厂商适配器尚未由本次正运动仿真验证；每个厂商和具体卡型仍需单独验证。

## 复现方法

在仿真器仍由 ZDevelop 承载且 SDK 会话可连接时，运行：

```powershell
& '.\tools\MotionControl.ZMotionSimulatorCheck\bin\Debug\net48\MotionControl.ZMotionSimulatorCheck.exe' --rotary-assembly-simulator
```

退出代码为 `0` 表示场景通过；返回 `2` 且 SDK 报 `20008` 表示本次独立检查器未连接到仿真会话，不能据此判断仿真控制器或轴功能失败。
