# 十二轴六任务仿真验证

运行入口：`MotionControl.ZMotionSimulatorCheck.exe --complex-machine-simulator`。仅允许连接本机 `VPLC5xx-Simu`；所有轴使用正运动适配器，工位流程仅使用框架的逻辑轴与轴组资源协调器。

| 物理轴 | 逻辑轴 | 所属任务 |
| --- | --- | --- |
| 0、1 | A_X、A_Y | A 侧定位，两轴同时动作 |
| 2、3 | A_T1、A_T2 | A 侧检测工具轴 |
| 4、5 | B_X、B_Y | B 侧定位，两轴同时动作 |
| 6、7 | B_T1、B_T2 | B 侧检测工具轴 |
| 8 | Shared_Work_Z | A/B 检测共用，必须排队 |
| 9、10 | Transfer_X、Transfer_Z | 搬运任务，两轴同时预定位 |
| 11 | Feeder_X | 独立送料任务 |

测试先只读检查 0–11 轴和仿真控制器身份。全部停稳、无报警和限位后，才应用样例轴参数并启动流程。A/B 定位、搬运预定位、送料先并行运行；两侧定位都完成后，A/B 检测各自申请工具轴和共用 Z 轴。搬运等待两侧检测完成，送料等待搬运交接。

检查点：首轮至少七根轴同时运动；中途暂停后至少四根轴停在起点与目标之间；复位启动后，在一侧检测持有共用 Z 轴、另一侧排队时再次暂停；确认所有轴停下且占用计数归零；再次复位启动后六任务完成；共用 Z 轴始终仅有一个占用者，至少一个检测任务发生可观测等待；十二轴全部到位并返回测试前位置。不写任何 DO。测试过程会把物理轴 0–11 的单位、运动参数和软件限位临时应用为样例配置，结束时恢复十二轴位置和样例轴参数，并逐轴读回核对。

2026-10-25 在 ZDevelop V3.10.10 的 `VPLC5xx-Simu` 上连续实测两轮：十二轴只读预检通过；每轮首批七轴同时运动并中途暂停；第二次在共用轴占用和排队期间暂停，三根活动轴停稳且占用计数归零；再次复位启动后六任务完成，共用 Z 轴排队分别为 A 侧 7128 ms、B 侧 6224 ms；每轮十二轴均到位并恢复测试前位置。Debug/Release 编译均为 0 警告、0 错误，Runtime 回归检查全部通过。该结果验证独立轴并发、任务交接和同一逻辑轴仲裁，不代表多轴插补、不同轴之间的机械防撞或实物设备验收。

## 2026-10-25 基于行业案例的复核

### 参考案例给出的补充边界

- Rockwell MultiBelt 官方应用把多个独立移动单元、上下料工位、队列和移动单元之间的最小间距放在同一个输送应用里考虑。它说明复杂并发设备除了“多个轴同时动”，还可能有不同机构之间的空间避让与跟随关系。参考：[Rockwell MultiBelt Conveyor Control](https://www.rockwellautomation.com/en-no/support/product/product-downloads/innovation-center/multibelt-conveyor-control.html)。
- 正运动公开的 ZMotion PC 函数库手册列出多轴直线、圆弧和螺旋插补 API；这类单条协调轨迹与本测试用多个 `MoveAbsoluteAsync` 并行下发，是两种不同能力。参考：[ZMotion PC 函数库编程手册](https://www.zmotion.com.cn/upload/%E6%AD%A3%E8%BF%90%E5%8A%A8%E6%8A%80%E6%9C%AF-%E3%80%8AZMotion%20PC%E5%87%BD%E6%95%B0%E5%BA%93%E7%BC%96%E7%A8%8B%E6%89%8B%E5%86%8CV2.1%E3%80%8B.pdf)。

### 本轮实际仿真结果

复核前一次运行时，检查器先通过中途暂停，随后因只轮询两个步骤名称而错过共用轴短暂争用窗口，报出“没有同时观察到持有者和等待者”。这条失败只能说明检查器的观测条件不可靠，不能据此判定框架的轴组协调失败。检查器现已改为直接记录等待者、持有者及争用事件，并在应用轴参数后重新读取运动基准位置。

随后在 ZDevelop V3.10.10 的 `VPLC5xx-Simu` 上重新运行 `--complex-machine-simulator`，结果如下：

- 物理轴 0–11 逐一只读检查通过；轴停稳、无当前报警和限位，起始位置均为 0。
- A/B 两侧定位、搬运预定位、送料共七根独立轴同时运动；暂停发生时七根轴均位于起点和终点之间，暂停完成后全部停稳。
- 复位启动后，确认一侧检测任务持有 `Shared_Work_Z`，另一侧正在等待同一轴组；当时三根轴运动。再次暂停后轴全部停止，共用轴持有数归零。
- 再次复位启动后，六个流程全部完成，十二轴到位；A 侧实际等待约 4.5 秒，B 侧先取得资源、等待为 0。
- 十二轴返回测试前位置；之后将 0–11 轴工程单位、软限位、速度、爬行速度、加减速度恢复为项目样例值，并逐轴读回核对。最终 ZDevelop 显示 `UNITS=1`、软限位 ±100、轴位置 0、当前轴状态字 0；ZSimu 输入均未触发。检查器没有调用 DO 写入接口。
- 最终代码下 Runtime 回归全部通过；整套解决方案 Debug、Release 编译均通过，0 警告、0 错误。

### 能据此确认的能力与未覆盖项

本次验证确认的是：单张 ZMotion 仿真卡上 12 根映射轴的独立点位并发、六个工位流程的并行与信号交接、整机暂停/复位续跑、同一逻辑轴组的互斥排队，以及失败后轴位置和样例轴参数恢复。

本测试没有验证同一轨迹中的多轴直线/圆弧插补、独立移动单元之间按距离/几何位置避碰，也没有验证视觉、传感器、气缸动作和真实设备安全回路。当前 `IAxis` 对外提供单轴动作；`IAxisResourceCoordinator` 只防止同名逻辑轴被并发占用，并不计算不同轴之间的机械距离或工作区域。因此，以上项目仍需在后续设计或专门模拟场景中处理；本轮结果不能视为完整的多轴同步轨迹或机械防撞验证，也不能替代实物安全验收。
