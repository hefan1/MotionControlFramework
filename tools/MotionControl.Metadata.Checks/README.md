# F06 / F08 身份与数值检查

这个控制台项目使用临时配置和隔离内存设备，检查本次修改的真实软件入口。不会连接控制器，也不会使用生产目录。

## 修改对应关系

- `DeviceVariableDefinition` 的 `Name` 继续作为稳定键，`DisplayName` 只影响显示。工程单位、量纲、允许范围、显示精度、`SourceId` 和来源说明均为可选字段，旧版本配置缺少这些字段时仍能读取，界面显示未定义。
- `DeviceVariableStore` 负责初值、恢复值、流程写入和人工写入的范围检查。单位、量纲或稳定来源改变时不沿用旧值；纯显示名称和来源说明改变仍保留旧值。人工确认时的定义在最终写入锁内再次核对。
- `TaskResourceCatalog` 复制权威变量元数据，任务校验器拒绝已明确不兼容的量纲及单位，不执行隐式单位换算。缺少旧元数据会产生提示，不能据此宣称物理含义已验收。
- `DeviceVariableView` 把定义维护和当前值写入分开判断。任务会话已加载、后台读取/关闭尚未结束，或者设备准备、清料、退出仍在进行时，禁止改定义；弹窗返回保存时再次检查。请先关闭任务会话，修改后重新读取任务。原有当前值写入的整机状态和变量权限门槛保留，不能因为定义锁定而一律禁用。
- `TaskTeachPointOwnershipValidator` 在工程预览和应用之前检查物理映射变化。点位迁移须明确提供点位文件，并声明组的 `logicalAxisName` 与 `engineeringUnit`。原手动页的数据类保留这些字段，其布局、按钮和点击行为保持不变。
- `WaitAxisPosition` 的编辑和运行详情使用所选逻辑轴的单位，位置与容差都带单位，并关联精确轴。跨单位改轴会清除旧坐标输入，要求重新填写。

## 检查范围

检查旧配置兼容、有效零与未知、元数据复制与 JSON 往返、写入范围、旧值/旧确认隔离、任务会话期间定义禁改且合法当前值可写、量纲与单位不兼容、跨轴同编号点位、换控制器和物理通道、原点位保存数据类保留归属字段、正式工程预览拒绝和迁移后装载。

运行方式：在支持本仓库 .NET Framework 4.8 构建的环境编译并运行本项目，或由仓库统一的 V1.8 验证脚本执行。

## 明确保留的边界

旧点位文件只有物理 `axisKey`、没有显式逻辑归属时，无法独凭该文件恢复其历史机构身份。本次保持读取兼容并明确提示；不能把这一兼容结果说成已完成迁移验收。直接在原冻结轴手动页的历史数据上操作仍须按原维护流程核对。正式 WPF 页面布局、焦点、实际点击与控制器/实物动作需要 Windows Host 和现场证据，本控制台检查不能替代。

原有三参数 `TrySetOperatorValue` 方法签名保留，新增四参数重载接收确认时定义。仓库内只有 `DeviceVariableStore` 实现该接口，两个入口均已实现；外部自行实现 `IDeviceVariableStore` 的程序集需要实现新重载并重新编译，不能据此宣称所有已编译插件二进制无变化。

单位符号区分大小写，`mPa` 与 `MPa`、`mN` 与 `MN` 不可互换。只对明确等价的 `°` / `deg`、`µm` / `μm` / `um` 等别名作规范化。数值初始值、运行值、历史恢复值分别保留说明，`SourceId` 是配置声明，不能单凭它或本机更新时间证明硬件采样成功或仍然新鲜。
