# ROC-18：来源观察停顿的修复设计

## 目的与当前证据

设备、工艺和任务来源改变后，页面必须继续观察当前来源并撤销过期检查。PR #12 已完成来源归属隔离，但合并后 Windows 内部检查出现间歇性轮询停顿，不能据合并前通过而关闭 ROC-18。

首轮现场显示短轮询完成 32 次后停止，UI 仍能执行 Send 和 Background 操作。第二轮确认实际 WPF 为 `4.8.9363.0`，任务来源说明的 Tooltip 时长为 `2147483647ms`。这与 WPF 有符号到期时间比较的极值风险相符，但第二轮没有重现原停顿，不能把候选直接写成已确认的正式 Host 故障。

提交 `c3ada3dd` 已在 [push 运行 42761942117](https://github.com/hefan1/MotionControlFramework/actions/runs/42761942117) 取得两项明确失败。随后 [PR 运行 42761950372](https://github.com/hefan1/MotionControlFramework/actions/runs/42761950372) 在原来源未变场景中再次停顿：短轮询和页面刷新均已到期，唯一极长计时器的回调是 `PopupControlService.OnShowDurationTimerExpired`，全局缓存恰指向该计时器。这个现场把极值机制与原问题连接起来；据此实施下述修正。

## 方案比较与实施判断

| 方案 | 覆盖与代价 | 本轮判断 |
| --- | --- | --- |
| 启动时统一修正危险的 Tooltip 默认时长 | 正式 Host 和内部检查复用一个具体入口；覆盖普通控件和动态详情，显式样式值保持。默认持续时间从约 24.9 天变为一天。 | 极值回归和原现场已确认，采用此方案。 |
| 在任务页逐个设置 Tooltip owner 样式或属性 | 影响范围较小，但按钮、文本、输入框、树项和动态编辑字段均有不同入口，容易遗漏；其他正式页面仍使用相同危险默认值。 | 不作为共享调度故障的完整修复。 |
| 只关闭检查窗口的悬停提示 | 可减少偶发失败，但不能处理正式页面的同类到期调度风险。 | 不采用为产品修复。 |

以上是本次维护的实施判断，不另行更换技术栈、运行框架或操作员页面结构。用户已要求继续处理 ROC-18；实现、检查和进度同步在现有授权内推进。

## 生产改动边界

- 在 `Framework.Wpf/Compatibility` 中增加具体的 `ToolTipTimingCompatibility.Initialize`，使用公开的依赖属性元数据 API。
- 仅当针对 `DependencyObject` 的当前默认值为 `int.MaxValue` 时，将默认时长改成一天（86,400,000 毫秒）；旧运行时的有限默认值保持，控件或样式显式设置的时长仍按 WPF 原优先级生效。
- 正式 Host 在创建界面资源和控件前初始化；内部检查入口调用同一方法，不能在测试中另造一份“修复”。初始化允许同一启动流程重复调用，但不支持已有页面之后临时改变全局策略。
- 不修改 WPF 私有字段、不补丁系统程序集、不更换 Dispatcher 优先级；这是应用侧兼容防护，不声称修复了系统框架自身。
- 现有固定骨架及四个受保护页面的源文件、布局和命令保持。默认 Tooltip 的实际到期行为会受兼容处理影响，应在 ROC-13 正式 Host 走查中核对提示显示和页面刷新。
- 文件观察、设备连接、轴与 IO 命令、任务 Apply 的断连要求、报警和恢复证据保持原语义。

一天的时长远离有符号毫秒边界，同时保留足够长的提示阅读时间；用户仍可移动鼠标或按现有关闭方式收起提示。它不是永久显示承诺。新增显式 `int.MaxValue` 样式不在“只修正默认值”的保证范围内，应在代码评审中避免。

## 检查修正

两个“来源未变”正控从本次 Loaded 后的观察起点开始，记录原工作区和观察代次；在 UI 轮询之间见证两次不同的成功发布时间戳。不能使用构造时缓存，不能接纳读取失败或旧代次结果。窗口关闭会重置产品字段，因此返回后检查保存的见证结果，再执行原有页面、草稿和文件断言。

正常观察继续沿用原 2.5 秒最低观察和 5 秒结果等待。独立守护仅将计时器不再触发的情况退出并记失败，不放宽正控期限；原 180 秒进程守护保留为 UI 线程无法返回时的最后收尾。临时调度钩子、私有框架快照及十轮重复在根因证据充分后清理。

## 通过条件

1. 修复前新增两项回归因预期原因失败，日志保留实际时长、短/长到期值与全局缓存。
2. 修复后同一计时器回归、缺少后台发布的负控和原有来源变化/恢复/未保存输入检查通过。
3. Windows 正式 Host 构建、受保护布局、15 个内部检查项目和现有 Virtual 软件控制器 API 完整通过；独立复核无阻塞项。
4. 以实际合并提交验证主分支，再更新 ROC-18/ROC-23 的最后 TODO。正式 Windows Host 画面与实际设备验收仍分别记录，不由内部检查代替。
