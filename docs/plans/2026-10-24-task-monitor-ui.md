# 任务运行监控与分类步骤详情实施计划

**目标：** 按已确认图 2 实现 WPF 任务总览、步骤树表、按类型变化的只读详情，便于操作员定位等待与故障。

**架构：** 新建可选 `MotionControl.TaskEngine.Wpf`，只依赖任务引擎。Host 显式组合；Runtime 和厂商适配器不引用 UI。生产 Host 保持原有入口，独立 `--task-simulation` 启动模式只创建内存设备，整机按钮控制这个内存会话。

**技术：** .NET Framework 4.8、C# 7.3、WPF、现有任务引擎快照。所有新增方法和成员使用中文注释。

## 实施顺序

1. 在 Execution 增加不可变步骤诊断：已接受的轴终点、当时轴位置、输入条件、本次分支结论、写入值、延时剩余时间。诊断跟随调用 ID；完成后保存当时数据，不使用当前变量反推历史结论。
2. 创建 TaskEngine.Wpf/Monitoring：稳定的工位行和步骤行；按父调用关联重复子任务；并行同时显示；未进入和未选择分开；整机暂停覆盖活动步骤状态。
3. 创建 Views：上方任务表，下方步骤树与右侧详情；轴、条件、分支/资源、赋值与延时采用明确的显示分支。跟随执行、手动选中取消跟随、定位故障和参数折叠。步骤详情通过既有页面公开的只读定位方法选择逻辑轴、DI/DO 和设备变量。
4. Host 增加任务运行导航和独立内存仿真入口。仿真样例覆盖轴组、并行、条件、子任务、资源等待、IO 等待和故障恢复。程序启动不自动运行；复位后启动。仿真关闭等待后台工作收尾。
5. 中文键的中英文资源；单位、未知状态、未实现插补明确显示。界面不添加未接入的编辑按钮，不修改控制卡原生声明。
6. 增加诊断一致性回归（分支结论固定、相对目标固定、未知输入、暂停计时、重复调用区分）；构建并执行现有内存回归。通过 Windows Computer Use 观察和操作实际 WPF 界面；工具拒绝时明确记录未完成，不替代为截图推断。
7. 更新模块说明和验证记录，检查差异后中文提交本地 Git。

## 本期边界

- 本轮实现已讨论的运行监控页面与分类详情。完整任务增删编辑和设备任务文件选配仍按后续编辑器阶段开展；运行库不会被监控页更改。
- 所有示例值与输入注入只存在于独立内存设备。不开启 ZDevelop、不连接 SDK、不执行实物运动或输出。
- 操作员只读详情；条件成立不等于机构完成，DO 写入成功与反馈输入分开。
- 定义与运行快照关联，循环换轮时清除旧轮显示。完成节点的诊断明确标记为执行记录，不称为实时值。
- 本机任务会话目前只用现有全局变量配置提供名称和类型，执行设备仍是独立内存模拟对象；不会读取或写入 Host 生产变量值。任务页到既有页面的链接负责导航和选择对象，不代表任务引擎已接入生产运行时。
