# 轴映射配置页面设计

## 目标

为单台设备提供一个直观的控制卡选择与物理轴映射页面。使用者能按设计好的总线通道排布核对 `Axis0`、`Axis1` 等物理轴号，再为实际使用的轴填写中文设备名称和轴参数。

## 页面与配置

- 页面放在 Host 的“设置 → 轴映射配置”中，作为 Framework.Wpf 的通用 WPF 页面接入。
- 页面顶部只提供控制卡厂商、控制卡类型和轴通道数量三个下拉框。默认正运动、总线型、64 轴；首版通道数量选项为 8、16、32、64。
- 左侧表格按物理轴号列出当前卡容量内的轴通道；设备轴名称为空时显示未配置。
- 右侧面板编辑当前轴的中文名称、直线/旋转类型、工程单位、单位换算、软限位、手动调试速度和回零参数。
- 轴映射页不保存手动定位加速度/减速度或点动加速度/减速度。手动调试页的临时运动曲线输入与轴映射参数分开；厂商 API 必需的专属参数由对应适配器内部处理。
- 回零模式只显示控制卡原始数字；数字属于厂商定义，调试人员按当前控制卡和型号的手册确认含义。
- 检查操作验证轴名称重复、单位换算、软限位、手动速度、回零速度和回零加减速度。保存时使用 Runtime 的 `MachineConfigurationStore` 分别备份写入当前 MachineId 的 `HardwareConfig/MotionCards.json` 与 `HardwareConfig/AxisParameters.json`。
- `MotionCards.json` 保存厂商、卡类型和通道数量，并保留已有卡标识、适配器和连接文件；`AxisParameters.json` 保存已命名的轴通道和轴参数。未配置通道不写入 `axes`。
- 首版 Host 示例使用本机用户配置目录和 `Machine01`。实际设备 Host 后续注入现场 MachineId 和配置根目录。

## 边界

页面保存卡厂商和类型选择，但具体运动卡适配器仍由 Host 组合根明确引用；运行时热切换厂商不属于本页功能。页面只管理轴映射和调试参数，不执行运动命令。

## 参考工程参数对照

检查了 `Leadshine.CNC.POL_V2.2.05-20210929` 的 `AxisSetBase` 和 `SetAxisPanel`，以及 `版本库_202400613-V1.0.1.7_修改真空检测_恢复版` 的 `AxisSettingPage`、`EleAxisConfig`：

- 两个雷赛工程都会保存物理卡/通道和设备轴名称，也会保存机械换算、运动速度、加减速度、软限位或到位误差、回零模式和回零速度等轴参数。
- 旧工程还保存每轴回零顺序、轴组、轴启用状态；另一个工程把正限位、负限位和原点的 DI 通道及启用状态放在轴对象里。
- 雷赛轴基类还保存方向、输入有效电平、原点位置和不同档位的手动速度。位置计数和 Z 信号状态属于运行状态，不应当作为设备配置参数。

首版沿用通用价值高且当前调试页会使用的部分：物理轴映射、中文名称、轴类型、工程单位换算、软限位、手动调试速度、回零原始模式编号及回零速度曲线。手动定位加减速度和点动加减速度不属于各厂商语义一致的通用轴映射字段，因此不保存到该配置中；需要设置厂商 API 运动曲线时，由具体适配器负责。回零模式编号同时记录所属厂商，防止切换厂商后误用相同数字。`UnitsPerEngineeringUnit` 已代表每工程单位需要的控制器位置单位，不再同时保存重复的每转脉冲、每转导程和每脉冲距离字段。

自动生产动作的速度保存在命名工艺动作参数中，不在轴映射页另设一个固定自动速度；同一根轴可以在不同工艺步骤使用不同速度。轴映射页中的手动调试速度只供人工调机使用，运行时不会覆盖工艺动作速度。

IO 物理通道与有效电平继续由 `IoMapping.json` 管理。参考工程将轴限位和原点输入直接嵌在轴对象里，适合它们自己的硬件接线方式；本框架已有独立逻辑 DI 映射和 `ActiveHigh`，避免轴参数和 IO 地址各存一份。回零顺序、轴组、到位误差和工艺目标位置留给设备流程或工艺配置，不塞进硬件映射页。

轴方向取反、原点偏移、可选软限位开关和轴专用限位/原点输入引用，暂不作为首版通用页面字段：当前通用轴定义和各适配器还没有一致的运行语义。IO 接线与极性继续由 IO 映射管理。回零方向也不做统一字段；正运动的部分模式把方向编码在模式号内，而雷赛参考工程会另传 `home_dir`。将来接入雷赛时，如果其驱动接口需要额外方向或 EZ 参数，应作为雷赛适配器自己的配置项处理，不能假定回零模式编号已经包含全部参数。

当前正运动下拉框只列出 ZBasic 手册中可由现有单轴 DATUM 接口直接传入的常规模式号：1–6、8–9、11–16、18–19。数字不带动作说明；模式 0 是清错操作，模式 7 未在当前手册表中定义，模式 21 和编码器特殊组合需要额外厂商参数，首版不作为通用可选项。除已在仿真器验证的模式外，其余编号显示不代表已完成逐项运动验证。

后续接线任务需把 `AxisParameters.json` 中的通用字段转换到 Host 实际创建的 `AxisHardwareDefinition` 和所选适配器轴配置。页面保存成功只代表配置已写入，不能代替这一步的运行时接入。
