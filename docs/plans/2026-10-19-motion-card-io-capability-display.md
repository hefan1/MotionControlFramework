# 控制卡 DI/DO 数量读取设计

## 目标

控制卡连接后，在 IO 映射页展示控制器自带 DI/DO 数量、最大支持数量，以及 API 能扫描到的总线扩展节点和节点 DI/DO 总数。数量信息只用于查看和配置核对；实际设备使用哪些点位，仍由 `IoMapping.json` 中的逻辑映射决定。

## 边界

- 在 `Framework.Contracts` 增加单独的可选 `IMotionCardIoCapabilityProvider` 能力和中文注释的结果类型，不扩大基础 `IMotionCard`。
- 正运动实现通过 `?*MAX` 读取 `max_in`、`max_out`、`max_slot`；`max_in` 与 `max_out` 的首值表示控制器自带点数，第二值表示最大支持点数。
- 按查询到的总线槽位数逐个调用节点数量和节点信息 API，累加各节点的 IN/OUT 点数。
- IO 映射页显示只读摘要。适配器没有该可选能力时显示“此适配器未提供”；API 查询失败时显示错误，控制卡连接保持有效。
- 不用通道数量自动新增映射、不改动 IO 映射 JSON、不推断端子是否接有传感器或负载。

## 点数和编号范围

- `max_in`、`max_out` 的第一个数表示控制器板载点数，第二个数表示控制器支持的最大 IO 编号数量；它们不是当前接线端子的实时清单。
- 板载点数和总线节点点数用于查看实际安装规模；最大编号范围只用于检查配置中的通道号是否超出控制器规格。
- 扩展 IO 按地址块分配，编号范围里可以有未安装模块对应的空段。不要逐个读取所有编号来推算实际点数，也不要因某个编号读取失败就推断更高编号都不可用。
- IO 映射表只显示设备配置中已经命名的逻辑点位；工程师通过“添加 DI/DO”明确增加配置，不按规格上限生成空白映射行。
- 正运动地址分段的依据见《ZMC412 运动控制器用户手册 V1.6.0》第 4.3 节“CAN 扩展资源映射”；其他型号仍以各自手册和适配器返回值为准。

## 主要流程

1. WPF IO 映射页载入时先检查卡连接；未连接则提示连接后可读取。
2. 已连接且适配器实现可选能力时，调用只读查询。
3. 正运动适配器执行 `?*MAX` 并查询每个总线槽位的节点 IN/OUT 数量。
4. 页面展示卡载数量、最大支持数量和已扫描扩展节点数量。

## 错误与验证

- I/O 规格读取异常必须显示厂商错误上下文，不影响控制器连接，也不阻止正常的 IO 映射编辑和保存。
- 构建 WPF Host，使用 Windows 屏幕检查 IO 映射页的连接前、连接后和查询失败状态；在 ZDevelop 仿真器上核对查询结果与控制器规格信息。
- 验证页面读取数量不会增删、保存或覆盖逻辑 IO 映射。
