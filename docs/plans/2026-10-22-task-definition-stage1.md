# 任务执行引擎阶段 1：定义、配置引用与离线校验

**目标：** 在已确认的阶段 0 方案上实现可独立编译的任务定义模块，供后续引擎和编辑器共同使用。

**架构：** 新建 MotionControl.TaskEngine，依赖 Contracts、Runtime 和已有 Newtonsoft.Json；不引用 WPF、Host 或厂商适配器。用普通数据类、明确的节点类型分支和中文校验信息表达任务。本阶段没有任务执行方法。

**技术基线：** .NET Framework 4.8、C# 7.3；沿用 MachineConfigurationStore 的设备隔离、原子保存和备份。

## 实施步骤

1. 在 `src/MotionControl.TaskEngine/Definitions` 建立任务、顺序、并行、条件、运动、IO、变量、子任务和资源范围的定义。一类节点一份文件，定义中不保存线程、SDK 句柄或执行状态。
2. 在 `Catalog` 读取现有轴、IO、变量和示教点 JSON，只生成只读目录。示教点按现有物理轴键关联到逻辑轴，不改变旧文件。缺少可选变量或示教点文件时目录为空；损坏文件必须报告。
3. 在 `Validation` 分开校验结构、动作参数、类型、引用和子任务循环。错误包含任务 ID、节点 ID 和字段路径；未知的卡能力报告待核实，不能当作支持。
4. 在 `Configuration` 显式按 kind 读取已知节点，拒绝未知节点、未知字段、未来 schema 和 CLR 类型元数据。保存前校验，校验失败不覆盖原文件。
5. 新建 `tools/MotionControl.TaskEngine.Checks`，仅引用任务模块，检查正常/异常定义、现有配置读取、JSON 往返、备份、错误保留、循环引用和程序集边界。只在临时目录写测试数据。
6. 编译 Debug/Release，运行离线检查；记录覆盖范围，检查差异后使用中文说明提交本地 Git。

## 范围限制

- 不接入 Host，不增加 UI，不连接控制器，不调用运动、伺服或输出指令。
- 不修改原生 API 声明、现有设备配置和运行恢复文件。
- 任务定义检查通过只说明定义和引用有效，不证明轴已回零、实时条件满足或设备能执行。
- 同卡直线协调运动仅定义参数；厂商能力、资源仲裁、动作执行和检查点在后续阶段实现。
- 本期条件支持明确比较及 All/Any/Not；通讯、计算动作和子任务参数绑定后续单独完善，未知 kind 必须报错。

## 验证方式

使用 Visual Studio MSBuild 构建新增检查项目，然后执行其 Debug 和 Release 输出。预期每个检查显示中文通过说明，总失败数为零。不运行厂商仿真检查程序。
