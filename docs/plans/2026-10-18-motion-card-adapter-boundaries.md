# 运动控制卡适配边界实施计划

> **For Codex:** 按此计划在当前仓库内完成文档边界整理；不接入未确认型号的雷赛驱动。

**Goal:** 根据雷赛参考工程，明确不同厂商、总线/脉冲卡型如何通过稳定的基础契约接入框架，同时保留卡型差异。

**Architecture:** 设备流程依赖最小公共轴和逻辑 IO 契约。具体适配器围绕 SDK/API 家族实现转换；仅在真实设备流程需要时增加可选能力，不扩张所有卡必须实现的基础接口。

**Tech Stack:** .NET Framework 4.8、C#、现有 Contracts、WPF Host；本次只更新架构文档。

---

## 参考工程观察

- `Leadshine.CNC.POL_V2.2.05-20210929` 分别组织 DMC5610 与 DMC5410 卡对象和运动参数集合。
- `版本库_202400613-V1.0.1.7_修改真空检测_恢复版` 的 `PrimLESI` 使用 `LTDMC.dmc_*`，由具体实现完成距离和速度换算、回零参数设置及状态读取；其 `IMotionCard` 同时包含大量轴、插补和触发能力，部分方法未实现。
- 推荐采用最小公共契约加按 SDK/API 家族划分的适配器；避免一个覆盖全部厂商能力的大接口，也避免按厂商品牌把不同行为的卡强塞进同一实现。
