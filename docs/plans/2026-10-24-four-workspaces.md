# PDF 四个工作区实施

依据 `output/pdf/运动控制上位机_UI交互设计讨论稿_V1_20261024.pdf` 第 6、8、10、17 页及其细节说明，实施设备总览、任务配置、列表式任务编辑、当前报警。已有外壳和轴、IO、变量页布局保留。

1. 设备总览：接入当前传统 Runtime，显示整机状态、工位卡片、当前动作、报警摘要和页面采样时间。没有产量、节拍、独立工位状态或结构化等待数据时明确提示未提供，不推断、不显示虚假 0。
2. 当前报警：读取同一 Runtime 的报警快照，搜索、稳定选择、四块处理说明和工程诊断；条件仍有效与待复位明确区分。页面不清报警，不发轴/IO 指令。现有报警未提供关联轴/IO 的稳定名称，按钮进入已有监控/手动页，不假装精确定位。
3. 任务配置：复用完整草稿存储，增加工位行内编辑、设备文件版本、任务库草稿状态。版本来源是已应用文件，不冒充正在执行的会话。草稿/检查/应用边界保持。
4. 编辑器：保留树形容器和稳定 ID，将行分为步号、动作、类型；运动组显示目标摘要表和选中轴的独立参数。操作只编辑定义。
5. 新增独立四页预览，不创建任何控制卡或现场恢复服务；示例状态始终标明离线示例。用真实临时文件、控件事件、两种语言和窗口尺寸检查，并编译 Host、执行相关回归。

正常 Host 的顶部按钮继续控制传统 Runtime，列表任务仍走现有独立仿真入口。历史报警持久化、真实任务统一执行入口和跨进程任务恢复未纳入本轮。不得把内存示例或离屏渲染说成真实设备/桌面验收。

四页已经实现，相关构建和共 109 组内部检查通过。屏幕工具初始化及重置重试均失败，因此实际桌面验收未完成。操作说明见 `src/MotionControl.Host.Wpf/Operation/README.md`，详细结果见 `docs/verification/2026-10-24-four-workspaces.md`。
