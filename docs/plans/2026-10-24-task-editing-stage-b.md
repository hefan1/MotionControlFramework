# 任务配置与列表编辑第一轮实施

用户已同意按《UI 交互设计讨论稿 V1》推进。本轮完成阶段 B：任务配置、任务库、分类步骤编辑及草稿检查/应用；保留已有页面布局。

## 实施顺序

1. TaskEngine 增加具体的设备任务草稿包存储。复用现有节点、清单、目录、严格 JSON 和校验；不添加硬件调用。草稿集中保存到 `Drafts/TaskWorkspace.json`，取代讨论稿中分别保存多个草稿文件的建议，保证一次草稿保存完整。
2. 应用前检查当前文件签名、引用和版本。写前备份全部受影响文件并记录恢复标记；出错回滚，意外退出后阻止加载半应用配置，提供恢复入口。运行文件仍使用 `Tasks/*.json` 和 `Parameters/TaskMachine.json`。
3. WPF 实现任务配置的工位安排与任务库页签，以及列表式任务编辑。具体表单按运动、信号、条件和资源分别组织；不使用反射通用表单，不增加厂商 API 依赖。
4. Host 增加“设置 → 任务配置”入口和已有配置页的只读定位；仿真会话未关闭、传统运行时仍连接时禁止应用并说明原因。现阶段任务编辑仍服务内存任务配置，真实任务执行接入在后续阶段。
5. 验证草稿隔离、错误引用、稳定 ID、应用冲突、失败回滚、意外退出恢复和中英文 WPF 构造。优先尝试屏幕交互；工具不可用时明确记录，不将离屏检查称作屏幕验收。

## 本轮边界

不发送运动、伺服或 IO 指令；不更换顶部启停语义。协调插补执行尚未接入，编辑入口显示原因并禁用。重启恢复、生产首页与完整报警页按后续阶段实施。
