# 停机报警跨连接交接：沙盒验证与待完成项

## 当前状态

本工作树是**尚未合入主工作区的验证候选**，不能作为已完成的通用设备交付。它针对上次复现的“断开后丢弃旧 Runtime，重连创建空报警服务”增加了未知交接门禁，但首次迁移、可信核查与现场安全策略仍未完成。不要手工创建或删除交接文件来绕过门禁，也不要将本次模拟结果当作实机验收。

## 候选实现

- `AlarmContinuityStore` 在已存在可信结束记录的前提下，先刷新待交接文件，再允许后续 Runtime 操作。旧记录缺失、损坏、被占用或遗留待交接文件均按未知处理；报警历史仍只是查询资料，不是控制账本。
- Host 在正常断卡时核查原报警记录和 Runtime 可观察到的收尾；未复位的停机报警形成独立的交接未知报警，保留原来源和代码作为本进程中的核查线索。旧来源迟到的停机通知会锁定当前 Runtime，并向当前报警服务报告交接未知；等待轴状态时收到该锁定的回归用例拒绝后续轴复位。
- `MachineRuntime` 把报警交接未知作为独立门禁，在整机复位下发轴和工位动作前检查，并通过原恢复门禁阻止准备、清料和自动启动。受控停止入口仍可调用；资源、清料及原恢复证据没有由报警复位清除。
- 正常关机只有在设备项目明确声明自身报警来源均受已跟踪流程管理，且任务会话、工位、监控、通知和断卡收尾已经确认、没有未知报警时，才可关闭本次待交接文件。本轮只为 `WeldingExample` 软件仿真设备声明该能力；其他设备不默认具备。

## 继续解决后才可合入

1. **首次部署和旧项目迁移尚无可信初始化流程。** 当前候选会将缺失文件视为未知，而不会自动创建安全记录；既有项目升级后会被拦截。需要设备项目提供覆盖旧来源和现场的可追溯核查、明确设备身份和版本，并完成可靠初始化及恢复流程。不得把缺失文件或历史日志当成安全证明。
2. **未知状态没有经设备批准的解除入口。** 旧任务一次性执行 ID、多个条件、无法重采的历史报警等，需要设备项目提供有明确覆盖范围的当前有效证据，或受控维护核查和审计。核查通过后仍须显式报警复位，不自动开始生产，且不能解除其他报警、急停、资源和清料门禁。
3. 当前记录只绑定 `MachineId`，尚不足以识别同名设备配置复制、工程导入或配置变化；需完善稳定设备身份和迁移校验。完整断电、文件写入失败和文件系统持久性边界尚未实机验证。
4. 当前条件报告和轴复位命令之间仍需补齐并发排序证明；旧来源迟到的 Host 端到端测试、多条件只恢复一部分、轴/DO 常规手动动作的设备级维护权限仍需补测及明确策略。当前持久保护由正式 Host 接入，直接自行构造 Runtime 的其他宿主尚未自动接入。未测试实机、其他厂商驱动、真实安全回路或生产循环。
5. 复核发现连接页在 Host 创建 Runtime 前调用适配器，正运动连接还会应用轴参数。候选已把持久记录的打开提前到创建控制卡之前，但报警交接未知或记录读写失败时，当前连接仍可能应用参数；需要设备适配器提供受控的只读核查路径或在应用参数前执行明确门禁。离线打开软件后未完成连接收尾也会保守保留待交接记录，需要进一步处理其可用性。
6. 为防止当前候选影响正常项目，代码保留在独立工作树，不合入主工作区。主工作区仍存在先前记录的跨连接锁存丢失，不能把候选验证结果当成主工作区已经修复。
