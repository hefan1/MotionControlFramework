# V1.8 活动会话上下文隔离检查

## 结论

任务目录绑定和设备总览工位选择隔离已完成源码修复，并通过本地内存检查及正式 Host Release 构建。此次检查没有连接控制器，没有操作旧 Sandbox，也没有进行屏幕验收或实物验收。

## 发现与修复

### 任务目录与实际装载会话分离

- 复现：装载任务会话后修改保存目录中的 IO 映射，再刷新关联目录。
- 原问题：任务运行页会重新读取磁盘目录，将后续保存的配置误显示为当前运行会话的目录。
- 修复：会话存在时读取其冻结的 `TaskDevice.Catalog`；刷新目录不会越过当前会话回读磁盘。关闭会话后才读取当前保存目录。页面说明明确区分“已加载会话的冻结快照”和“当前保存配置，尚未装入任务会话”。
- 检查：临时配置在会话中增加 `DI_Later` 后，显示目录仍与会话目录对象相同且不含 `DI_Later`；安全关闭会话后，保存目录刷新才显示该输入。
- 额外检查：停止/关闭会话后若保存的 IO 映射无法解析，目录读取错误和原始 `IoMapping.json` 诊断继续显示，不被“停止成功”文字清除。

### 设备总览旧工位选择跨上下文保留

- 复现一：同一 `MachineRuntime` 断开并重连，保持相同工位 ID。
- 复现二：同一 Runtime 和控制器连接中，替换任务会话对象并保留 `S01` 工位 ID。
- 复现三：正式生命周期将 Runtime 置为 `null`，重连时再创建新 Runtime；以及工位状态采样期间由 C# 入口切换为任务入口。
- 原问题：总览能按相同工位 ID 恢复旧选择，界面可能把旧会话详情或导航目标带入新会话。
- 修复：比较 Runtime 对象、连接会话、控制权来源和任务会话对象。观察到上下文变化时清除工位行选择和详情，禁用定位按钮，并提示操作员重新选择；重选要求会跨过 Runtime 暂置为 `null` 的中间态保持，首次连接仍保留默认选择。采样期间控制权改变时丢弃本轮工位数据，定位前后再次核对当前控制权。任务会话身份缺失、为空或读取失败时清空并隐藏工位行，明确显示身份未确认；身份恢复后仍须重新选择。普通同会话刷新保留有效选择。
- 检查：重选后显示新会话的工位名和步骤；等待输入定位指向新会话的 `DI_New`；工位运行定位指向新会话 `S01`。运行时对象重建和控制权切换边界也已覆盖。所有只读定位都没有调用内存卡。

### 任务会话读取期间身份变化

- 复核发现：工位会话身份在一次刷新中变化时，工位行虽已丢弃，但同轮读取的资源摘要仍可能被显示，并覆盖整机恢复提示；身份读取入口缺失、返回空和抛异常也曾共用“采样期间变化”的错误文字。
- 修复：任务身份未确认或前后不一致时丢弃同轮资源摘要；整机恢复阻断仍显示在设备总览。明确区分任务未读取、身份未确认、采样期间身份变化和身份读取异常，并保留异常信息。
- 检查：分别覆盖身份入口缺失、返回空、抛异常及读取前后会话对象变化；会话变化时断言旧资源摘要被隐藏、恢复原因仍可见且不会把下一步引向旧资源。

### 顶部任务命令错误反馈

- 复核发现：顶部启动或暂停开始时已清除旧错误对象和诊断，但旧错误文字可能仍显示在状态区。
- 修复：清除当前错误时同步清空对应可见状态文字；命令成功后再显示本次成功反馈。
- 检查：用内存运行时走通顶部复位、启动和暂停；分别确认成功文字与诊断区域状态；另覆盖旧错误后顶部命令失败时，旧错误文字和诊断同时清除。
