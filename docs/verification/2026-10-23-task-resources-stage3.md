# 阶段 3：任务资源仲裁与显式互锁验证

日期：2026-10-23。

## 实现范围

独立任务模块现已支持完整资源组排队、共享轴/输出/命名区域互斥、进入/退出条件检查、异常待确认和显式恢复。复用已有任务定义、条件求值、目录、变量存储、JSON 存储及运行控制。

本轮为**纯软件内存仿真验证**。没有连接 ZDevelop/ZSimu 或实际控制卡，没有运行 Host，也没有执行真实运动、伺服使能或物理 IO 输出。

## 新增 16 组检查

| 检查 | 已观察结果 |
|---|---|
| 完整组原子申请 | X 被占用时 X/Y 整组等待，没有先占 Y；独立 Z 同时可执行 |
| 冲突顺位 | 暂停等待者保留顺位，后来的冲突者不能插队；取消后后继正常执行 |
| 等待清理 | 取消和超时只移除自己的申请，不释放其他运行，不写后续 DO |
| 排队目标与回零 | 取得轴后才读取变量目标；Home 也按轴占用排队 |
| 进入/退出互锁 | 未知 DI 阻止进入；退出需位置、DI、变量同时满足；暂停时不释放，外部修改原定义不影响冻结条件 |
| 进入失败 | 位置不符、未使能、未回零、有报警均等待超时；正文前失败/取消不留下 Blocked |
| 异常与恢复 | 正文失败保留整组 Blocked 和已写输出；未知退出 DI、有报警、空确认均拒绝恢复；通过后放行，旧 ID 再次恢复拒绝 |
| 退出超时 | 正文完成但旧 ExitCondition 无效仍隔离；条件恢复并显式确认才能释放；位置未满足不能靠确认说明放行 |
| 取消运动 | 取消暂停中的范围后轴停止，资源仍待确认；ConfigureAxis 不能覆盖待确认轴 |
| 并行范围失败 | 一组失败取消另一组，内存轴停止，两组分别留下待确认记录 |
| 子任务继承 | 子任务沿用范围占用，不重新申请造成自锁；连续范围正常释放后再次申请 |
| 设备与快照隔离 | 不同设备实例的同名区域互不占用，旧快照不随后台释放改变 |
| 使用校验 | 缺少轴/DO、子任务中遗漏资源、隐藏嵌套、未选分支中的嵌套、范围内并行均拒绝；错误提供范围及引用节点 |
| 互锁字段 | 空条件、缺少或非有限位置、超行程、重复轴/DI、DO 误作 DI、遗漏 Expected、冲突退出配置均拒绝 |
| JSON 持久化 | 旧 ExitCondition 可读，新互锁往返不丢字段；修订保存留备份；未知互锁字段拒绝 |
| 可运行样例 | ResourceTransfer.json 完整执行，X 从 0 到 10 再到 0，内存输出最终 OFF，资源全部释放 |

额外核对：自定义资源不能使用 Axis:/Output: 保留前缀；执行前后没有加载 WPF、Host 或厂商适配器。源码未增加厂商 SDK 或 P/Invoke 调用。

## 实现复查

- 协调器在短锁内检查整组冲突，无 await 或设备回调；等待时不持锁。
- 设备配置、占用取得和恢复采用一致的设备锁 → 协调器锁顺序，避免配置入口在检查空闲后覆盖新占用。
- 异常范围保留的记录只包含资源组、身份和退出条件，不持有整个 TaskRun 或任务正文。
- 正常退出的条件核对与释放在同一次运行许可内执行；异常清理不会自动清除 Blocked。
- 类型、成员、方法均有中文说明；按定义、校验、协调、执行、场景和检查拆分文件，无新服务容器或厂商耦合。

## 明确限制

1. 区域名由设备作者明确定义。进入检查不是连续监控，没有几何避让或自动路径规划。
2. 完整组申请并禁止嵌套、范围内并行，用于避免资源锁循环等待；变量/外部信号的业务互等只能由有界超时和等待详情定位，尚无完整业务依赖图检测。
3. 异常恢复需要明确确认说明和原退出条件复核；位置不满足时继续隔离，尚无占用状态下的人工撤离动作入口、UI 权限或恢复审计存储。
4. 没有退出条件的正常范围，按作者定义在正文完成后释放；异常范围没有退出条件时依赖调用方人工核实的说明。不能将此用作实际机械安全认证。
5. 状态仅在同一内存设备实例内共享，不持久化资源申请/待确认，不提供跨进程生产恢复。
6. 旧 Runtime/C# 工位协调器保持原行为；两套执行入口尚未共用实际设备资源。后续接入硬件时必须统一实际动作入口和停止确认，不能混用两套锁控制同一台设备。
7. CoordinatedMove、多轴插补、真实回零/停止与编辑器 UI 本轮未实现。厂商替换边界仍由实际设备适配层负责。
