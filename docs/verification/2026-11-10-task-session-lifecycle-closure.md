## 代码入口与职责

- `src/MotionControl.Host.Wpf/Tasks/TaskMonitorLauncher.cs`：接收读取/关闭操作，固定并核对页面上下文，将可信结果挂到监控界面。
- `src/MotionControl.Host.Wpf/Tasks/HostTaskSessionLoadOperation.cs`：一次装载、准备安装、发布资格、失败回滚及重试。Host 在同一调度上下文调用它；后台仅执行读取，未增加跨线程任意调用的公开契约。
- `src/MotionControl.Host.Wpf/Tasks/HostTaskSessionLoader.cs`：原有配置和正式任务设备的具体装配，本轮未修改。
- 上一轮的 `TaskMachineOperations` 继续负责复位、启动、暂停、终止，不把装载逻辑并入它，不新增庞大管理器。

## 保留的保护与实际边界

准备安装代次仍在通知订阅者前通过 out 参数记录，订阅者抛错后也能定位本次安装。回滚必须比较原安装代次，不能覆盖另一操作的新定义。清理失败保留会话引用与控制权证据，下一次关闭或读取可重试；超时不等于停稳。已发布会话原有关闭超时、迟到结果不清除画面、失败重试及资源核查行为保持原有检查。

本轮移除页面里的清理委托和单独的清理任务字段，改为具体装载对象。页面代码净减少不代表整个仓库总代码减少：新增独立实现和回归测试是本次交付的一部分，不能称作全仓库已经瘦身。

## 验证证据

1. 原实现专项复现：[42694017057](https://github.com/hefan1/MotionControlFramework/actions/runs/42694017057)。程序编译成功后明确报 `PENDING_LOAD_CLOSE_RETURNED_EARLY`；工作流专门确认该预期失败，不把该运行的绿色状态误解为原功能通过。
2. 迁移完整验证：[42694972829](https://github.com/hefan1/MotionControlFramework/actions/runs/42694972829)。同一 Windows 工作区先观察原实现失败，再实施迁移，专项普通关闭/上下文切换通过；五项结构检查、十个受保护文件、正式 Host、15 个内部检查项目、现有单/双软件控制器及任务操作协调 API 均通过，随后提交生成的源码。
3. 最终提交还由原常规只读 Windows CI 复验，具体最终 SHA 和运行链接以 [PR #10](https://github.com/hefan1/MotionControlFramework/pull/10) 的最新交付说明为准，不用历史版本的结果冒充新代码通过。

新增 `PendingTaskLoadCloseChecks.cs` 复用已有 **无轴** 连接时序设施，只验证实际 Host 装载代码和 Runtime 持权生命周期，不属于运动或屏幕验收；该组纳入原操作页检查，总组数从 64 增至 65。没有新建 FakeAxis、内存运动模型、控制器程序或厂商空驱动。运动 API 回归仍调用仓库已有独立软件控制器。

专项第一次构建曾因自定义输出目录使 Host 找不到固定位置的软件控制器文件而失败；修正为先构建原软件控制器固定路径输出再构建专项程序，不将环境/构建错误当作预期的产品缺陷复现。

## UI 及交付清理

轴映射、IO 映射、轴手动、IO 监控和主窗口的 XAML 与对应 `.xaml.cs` 共十个文件均与 `18ab5a9` 基线一致。临时迁移脚本在成功提交时删除，临时迁移工作流也在交付清理时删除；保留常规只读 CI 与正式回归，不保留自动改写源码的常驻流程。

## 仍未关闭，不能由本批结果代替

- 整个 App 的启动、连接、应用退出以及专用退出入口的职责仍需专项整理；本批覆盖 `CloseTaskSessionAsync` 与 `SetMachineContextAsync` 的在途装载交接，不宣称所有退出路径已经统一。
- Host 逐卡混合品牌选择和配置迁移尚未实现。
- ZMotion 原厂 SDK 软件控制器调用链及雷赛、固高等新品牌适配未由本批执行；Virtual 成功不是原厂 SDK 成功。
- 正式 Host 屏幕走查，以及物理限位、制动、安全回路不在本批验收范围。
- 本轮进行了主代理源码复核和自动化验证，没有宣称独立第三方审查。
