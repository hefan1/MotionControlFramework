# PDF 四个工作区验证

## 实现范围

设备总览、当前报警接入正常 Host 的传统 Runtime；任务配置增加文件版本、草稿状态和工位编辑入口；步骤编辑增加分栏树行、可见未保存标记和多轴目标表。原轴、IO、变量页布局与厂商 API 未修改。传统流程页只添加按名称定位方法。

`--ui-workspace-preview` 在控制卡与现场恢复服务创建前返回，提供独立四页预览，数据目录与正常 Host 及旧编辑预览分开。

## 检查

- 使用 Visual Studio 18 Community MSBuild 构建 Host 及四个检查项目，Debug 构建成功。
- `MotionControl.OperatorPages.Checks`：6 组通过。覆盖无来源未知、真实 Runtime 类型的状态观察、卡/安全/流程入口禁止调用、12 工位、暂停覆盖、报警条件恢复待复位、非停机提醒消失、搜索、稳定选择、多语言、Host 导航返回原实例、工位行内按钮、同任务重复定位保留输入、文件版本与检查状态、每轴速度切换保存。
- `MotionControl.TaskEditing.Checks`：12 组通过，原草稿、引用、回滚、冲突和编辑保护继续有效。
- `MotionControl.TaskMonitor.Checks`：4 组通过。
- `MotionControl.TaskEngine.Checks`：定义/存储 22 组、执行器 53 组、整机调度 12 组通过；执行后仍无 WPF、Host 或厂商依赖。
- 共 109 组内部检查。全部使用内存设备、带调用保护的卡对象或临时配置目录，没有连接正运动仿真器或任何真实硬件，没有发送伺服、运动或 IO 输出。
- 四页在中文/英文、1200×780 和 824×550 内容区尺寸进行了离屏构造与渲染。已检查输出图，修正类型列对齐、整行选择、紧凑表头换行、卡片列数、状态横幅颜色和常用运动参数的位置。
- 原 PDF 是设计历史快照，本轮没有改写 PDF 或 AI 图像，界面以实际 WPF 控件实现。
