# 操作员总览与统一工位运行入口核对

日期：2026-11-04。范围为运动控制页面的信息组织、真实状态来源和关联定位，不是十三轴生产流程的完整验收。

## 本轮改动

- 运动控制分类下用“工位运行”替代“流程状态”和“任务接入状态”两个入口；旧代码的关联导航也归入该入口，不保留重复页面。
- 设备总览的主体显示当前执行方式的真实工位。任务列表读取当前会话快照；C# 读取实际工位对象，不借用另一执行方式的步骤。C# 契约未提供独立工位状态时，明确标注整机状态。
- 总览和工位卡片不再默认展示产量、完成次数和周期；保留底层数据及旧控件兼容性，不删除已有运行记录。
- 工位卡片突出当前动作、明确等待条件和相关报警。连接诊断默认折叠；断连、未读取流程和来源读取失败明确显示，失败不沿用旧卡片。
- 点击卡片定位实际工位；报警来源只有在唯一匹配工位名称或稳定标识时提供定位。定位不创建会话、不复位、不启动、不切换设备控制权。
- 工位运行页的日常启停使用顶部统一按钮；会话直接控制和已有产品记录入口放入默认折叠的工程区。工程能力及其原有准入检查保留。
- 外壳布局，以及轴映射、IO 映射、轴手动和 IO 监控四个已确认页面的源码未修改。

## 正式 Host 屏幕核对

通过 computer-use 技能操作实际 `MotionControl.Host.Wpf.exe`。每轮按窗口标题及完整 exe 路径确认目标；正常启动，未使用任务预览窗口或内部检查程序冒充正式界面。

1. 任务列表使用 `tmp/rotary-motion-internal-20261103` 隔离配置根，连接本机软件控制器端口 19583。只点击“读取设备流程”，没有复位、使能、回零或启动。总览显示初始化和四个工位，五张卡片在 1440×900 窗口可见；卡片正确显示等待复位及尚未开始执行。点击压合工位卡片后，工位运行页选中压合及其步骤。空报警表不再占据步骤区域。
2. C# 使用 `tmp/operator-code-ui-20261104` 隔离配置根，设备定义为 `RotaryMotionValidation`、执行入口为 `StationFlows`。配置只复制硬件、参数和任务，不复制草稿、Runtime 或恢复证据。实际总览显示上料、焊接、压合、旋转与下料、复检分拣五个 C# 工位；状态明确为整机状态。点击压合卡片进入当前 C# 流程并定位压合，没有启动动作。
3. 最后使用标准输出 `src/MotionControl.Host.Wpf/bin/Release/net48/MotionControl.Host.Wpf.exe` 再次核对任务列表页和总览；此前的独立输出也均来自同一正式 Host 项目。
4. 关闭隔离测试前，实际轴监控显示 13 根轴已停止、速度零、未使能、未回零、无报警。本轮没有下发轴运动、输出或输入切换命令。隔离 Host 正常关闭后，结束本轮软件控制器；隔离配置保留。
5. 正常打开标准 Host，保留在“运动控制 → 设备总览”。默认 Machine01 的软件控制器未连接；旧恢复记录缺少四个变量的提示已确认，记录没有删除或改写，流程恢复仍关闭。未启动设备。

## 保留边界与下一轮

- 默认 `%LOCALAPPDATA%/MotionControlFramework/Configurations/Machine01` 配置、草稿和历史恢复证据没有被本轮隔离测试替换；正常启动本身仍按应用原有行为读取/保存必要状态。
- 当前软件控制器只用于连接和空闲页面显示，没有安装本轮生产反馈场景；不能由本轮结论推断回零、生产、停机、报警恢复或物理干涉已通过。
- 报警唯一关联与读取失败由内部检查覆盖；本轮没有在正式 Host 注入生产报警。
- 受控清料的操作员入口、跨会话资源恢复和清料后两种流程的完整回归，仍按 HANDOFF 原记录列为未完成，不因页面合并而视为打通。
- 后续以设备准备、工位等待、报警处理和恢复为实际操作链逐页核对；具体设备动作由设备项目或任务配置提供，不写入通用页面。
