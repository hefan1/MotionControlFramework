# V1.8 UI-03：配置变更记录的阶段性改动

## 本次完成

- 报警库页面接入现有 `ConfigurationChangeJournal`：定义校验失败记录为检查失败；实际文件保存调用分别记录成功或失败。不会推定操作者、字段差异或运行版本。
- 设备变量页面将定义文件保存与内存更新调用分别记录，并用同一操作关联 ID 连接。文件已写入而内存更新抛异常时，明确提示“内存状态待核查”；回调异常可能发生在内存已变化之后。
- 记录写入失败与配置保存结果分开显示。变量页的记录故障和内存状态提示不会被普通状态刷新覆盖；报警库在关闭保存时保留错误提示。长提示可滚动查看。
- 设备工程历史列表显示对象、阶段和结果；变量内存调用异常显示为状态待核查，详情显示操作关联 ID。页面说明仅显示最近 50 条及尚未全部接入的来源。

## 验证

2026-11-09，Release 解决方案编译成功（0 错误）；Windows Sandbox 操作员页面检查 64 组、失败 0；设备工程历史页独立检查 5 组通过。测试覆盖报警校验失败、文件锁定、记录路径故障、变量内存通知异常、只有一个历史记录名额、状态刷新和长提示滚动；测试使用独立临时配置，不连接实体设备。

正式 Host 在沙盒软件控制器和独立仿真工程中保存现有报警库，并在设备工程历史页看到报警库文件保存回执、操作关联 ID 和未知字段；截图：[报警库历史记录](evidence/2026-11-09-v18-fixes/ui03-alarm-history.png)。新版异常警告区域、报警库关闭弹窗的各分支尚未在正式 Host 人工场景逐一核对；相关异常由隔离测试及代码复核覆盖。
