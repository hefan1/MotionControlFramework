# 任务会话装载与关闭交接实施计划

> 执行：沿用 executing-plans，在独立分支直接实施；不合并 master。

**目标：** 将装载、安装准备定义、失败回滚从任务页面移到一个具体对象；关闭必须识别尚未发布的在途装载，不得提前成功。
**架构：** 保留 HostTaskSessionLoader 的文件装配职责，新增 HostTaskSessionLoadOperation 负责一次装载的生命期。页面只捕获当前上下文、挂接已核对的结果和显示错误。不增加程序集、泛型管线或新的运动模型。
**技术：** C# / .NET Framework 4.8 / WPF；Windows CI。
**设计依据：** 前一轮 architecture-closure.md 的未关闭事项，以及用户确认的模块职责清晰、初级开发者易维护原则。

## 固定约束

- 基线 18ab5a9857ab3542c86ff02b835ca30da0530e89，上一轮完整 CI 42659576194 已通过。
- 四个受保护页面与主窗口的 XAML 和后台共十个文件不修改。
- 使用现有软件控制器 API；本批不新增假轴、品牌占位驱动、原厂 SDK 或第三套状态机。
- 原有命令协调、停轴确认、持权、准备版本比较及失败恢复证据不放宽。
- 页面关联对象仍由 Host 调度上下文串行调用；IO 读取在后台执行，不把 UI 控件交给装载操作对象。

## 验证优先项

1. 读取任务尚未返回时请求关闭：关闭必须等待同一次读取，并拒绝发布。
2. 关闭和装载失败各自触发清理：共享同一次清理，成功后才能忘记原会话。
3. 安装准备定义时订阅者抛错或替换代次：只撤回本次安装，保留新代次。
4. 在途关闭跨设备上下文变化：仅恢复原 Runtime 的原准备定义，不读取后来替换的字段。
5. 超时和迟到结果不能清空页面中的会话证据；关闭重试沿用既有语义。
