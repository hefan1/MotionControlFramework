# 职责归位重构与问题关闭计划

> 执行方式：在当前独立分支直接实施并验证，不修改 master。参照 executing-plans 的逐项验证流程。

**目标：** 将正式任务启动、暂停、复位、终止的设备协调职责移出 WPF 页面；以真实软件控制器验证原有安全行为及旧会话隔离。

**设计依据：** 用户确认学习 Sophon 的职责组织方式，但不复制其源码、空驱动或简化停止行为。沿用现有 Contracts / Runtime / TaskEngine / MachineDevice / Host 项目，不新增通用框架、反射注册或新的状态机。

**实现边界：** 在现有 MachineDevice 桥接项目增加一个具体的 TaskMachineOperations 协调类。TaskMonitorLauncher 只提交操作和更新显示；Runtime 仍负责整机身份、控制权与安全状态，TaskMachineController 仍负责任务工步和停轴收尾。

## 不变条件

- C# / .NET Framework 4.8 / WPF；新方法、成员均有中文说明。
- 轴映射、IO 映射、轴手动、IO 监控及 MainWindow 的 XAML 和后台文件保持基线不变。
- 不新增 FakeAxis、内存运动模型或第三套软件控制器。
- 失联或上下文撤销后，仍允许原任务尝试停止；禁止旧操作恢复生产或把结果提交给新设备。
- 不宣称雷赛、固高、ZMotion SDK 或实体电机已经通过尚未执行的验证。

## 执行清单

- [ ] 先建立结构回归检查：页面操作方法不再编排 Runtime 与 TaskMachineController；在原源码上观察失败。
- [ ] 建立具体协调类及已绑定设备工厂，保留连接身份、控制权、停止优先与异常链。
- [ ] 将页面四条操作路径转为调用协调类，设备切换、断线与会话关闭时撤销原协调实例。
- [ ] 使用现有独立软件控制器运行复位、启动、暂停、终止、旧会话拒绝和异步启动撤销检查。
- [ ] 运行结构检查、保护文件检查、Windows Host 构建、内部回归和单/双控制器 API 检查。
- [ ] 记录问题关闭矩阵：已验证关闭、待验证、超出本批范围三类，不能用一个总的通过代替逐项证据。

## 重点复核

1. UI 异步返回前已切换设备，不得显示旧任务成功或启动新设备。
2. 运行许可已建立但任务启动失败，必须停止原任务并锁存原 Runtime 故障。
3. 暂停失败或反馈未知，不能转为成功或放开资源。
4. 关闭失败时保留原会话、资源及诊断，不以销毁页面代替设备停止。
5. 变更不增加 UI/厂商 SDK 对核心业务层的反向依赖。

## 验证方式与交付

当前会话容器没有 Windows/.NET Framework，源码机械迁移与验证使用隔离的 GitHub Windows 工作区。仅向本独立分支提交结果，不合并主线。用于迁移的临时脚本与工作流完成后移除，保留真正的生产代码、检查和中文说明。

现有 Host 逐卡混合品牌装配、新品牌 SDK 接入、App 全生命周期整理及正式 Host 屏幕走查不因本次命令职责重构自动完成，必须在关闭矩阵中单列，不能误标关闭。
