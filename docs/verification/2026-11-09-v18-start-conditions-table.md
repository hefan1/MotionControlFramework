# V1.8 UI-05：启动条件只读表格

## 原因和改动

交接 PDF 的 UI-05 指出，启动条件原来以一列文字混排，难以逐项核对来源与时间。`EquipmentPreparationView` 现将既有的部分内存观察按“条件、观察结果、设备采样时间、来源”分列，选择行后保留完整结果、来源和原有只读定位入口。列宽随界面尺寸变化；长文本可在详情查看。切换条件时详情回到开头，刷新当前条件保留滚动位置；列被拖宽时可横向滚动。控制来源显示为任务列表、C# 工位流程或未接管等明确名称。

目前这些来源没有提供设备采样时间，每行均显示“未提供”。页面中的“界面观察”时间仍单独标注；它不代表设备采样时间、有效期或原子快照。工位、恢复状态与 Host 缓存覆盖不完整，启动提交时仍执行原有完整门禁。

## 验证结果

2026-11-09，在 Windows Sandbox 软件控制器和正式 Host（独立仿真项目 `V18UiAuditProject/Machine01`）核对表格、未提供时间、选择停机报警及详情；不占用本机鼠标，没有执行回零或生产启动。截图：[启动条件表](evidence/2026-11-09-v18-fixes/ui05-conditions.png)、[选中报警条件](evidence/2026-11-09-v18-fixes/ui05-selected.png)。

沙盒操作员页面检查 63 组、失败 0。检查包含中英文切换、无连接与会话失效、稳定选择、设备采样时间缺失、长原因、0/40 工位、824×600 与 1200×800 的离屏滚动布局、程序化加宽列后的横向滚动、切换长原因及只读导航。

## 范围

这是已接入内存来源的部分观察，不是完整启动条件服务或真实设备采样。未进行真实控制器、其他厂商适配器及现场安全验收；沙盒软件控制器的结果不能替代这些验证。其他交接项分别处理。
