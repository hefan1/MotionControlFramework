### 1. 任务能力与准备引用

`MoveAxisGroup` 表示各轴独立目标和速度、全部完成后汇合，不能称为插补，也不承诺同时到达。此次修复提前拒绝正式设备尚未实现的能力，并没有实现组定位。已有 `InMemoryTaskDevice` 明确声明其内存组定位能力。普通 `ParallelGroup` 中的单轴动作单独判断，不因名称中带“并行”就误报组定位。

工位准备配置的纯校验放到任务核心中，正式准备加载器、任务工作区和工程导入复用同一规则。查询引用会指出 `Parameters/StationPreparation.json` 中具体字段；依赖缺失、循环、无效任务、轴及输出引用会阻止通过检查。修改准备配置后，之前的工作区来源签名失效，必须重新读取和检查。

### 2. 等待诊断与 C# 工位

等待项区分对象类别与稳定对象 ID，显示名称中的 `;`、`=` 等字符不再用于切割身份。`NotProvided`、`Unknown`、`Unstable` 和 `ReadFailed` 不等于 `Good`；空等待集合也不等于来源没有提供等待信息。

`IStationOperationStatusProvider` 是一个可选、只读的小接口，设备工位返回已经记录的内存快照。它不会让界面读取控制器、推进步骤、自动解析任意 C# 流程或授予动作许可。没有实现该接口的旧工位继续运行，界面须保留“未提供”的真实边界。

### 3. 变量及点位兼容

变量新增字段均为可选：`DisplayName`、`EngineeringUnit`、`Dimension`、`MinimumValue`、`MaximumValue`、`DecimalPlaces`、`SourceId`、`SourceDescription`。旧文件未填写时保留“未定义”，不能自动补成毫米或零。

`Name` 继续作为稳定引用键；显示改名使用 `DisplayName`。单位、量纲、稳定来源或允许范围改变后，只有仍符合当前定义的值才能保留。重新装入的初值明确标注为定义初值，不称为新的设备采样。纯显示名或来源说明文字调整不会重新定义数据来源。

操作员写值确认携带当时的定义，最终写入在变量存储锁内复核。旧确认窗口不能把按旧单位输入的数值写进新单位或新来源的变量。单位符号精确比较，仅明确等价符号规范化；不做 `mm` 与 `m`、`mPa` 与 `MPa` 等隐式换算。

任务已经装载或正在后台装载时，变量定义维护会被阻断；准备、清料和退出期间也不允许改定义。须先关闭任务会话，修改定义后重新读取任务，避免冻结的任务目录与新变量定义混用。符合原整机状态及 `AllowOperatorWrite` 权限的当前值写入仍然保留。最终保存定义会再次核对许可，不能用之前打开的编辑框跨过门禁。

原三参数 `TrySetOperatorValue` 签名保留，新增四参数重载用于核对确认时定义。外部自行实现 `IDeviceVariableStore` 的程序集需要增加该重载并重新编译；本次不承诺所有旧插件二进制兼容。准备配置 DTO 移到任务核心，引用旧命名空间的外部源码也应跟随调整并重新编译。

示教位置仍沿用原文件结构和 `AxisName + PointId` 复合身份。新字段用于声明归属，没有把旧坐标自动转换为新设备坐标。旧无声明文件可以在未改变映射时兼容读取，但系统会说明归属或单位未确认；不能据此声称坐标已经过现场核对。

### 4. 任务应用与中断恢复

任务应用会先生成全部待写入字节，再保存原文件字节和版本 2 备份清单。原文件 BOM、换行及编码字节纳入哈希；不存在的文件和空文件分别记录。恢复时先核对 pending 与备份清单一致，再核对每份备份和全部目标文件。

目标只能仍是原内容或本次应用内容。第三方修改、备份缺失/篡改、清单不一致、无哈希旧版记录均阻断自动恢复。静态冲突在任何恢复写入之前发现；若实际 I/O 错误造成部分恢复，保留 pending 和备份并如实报告部分完成，后续可以重新检查后重试。不得通过删除恢复标记强行装载。

编辑锁协调本项目的应用入口，哈希复核加逐文件替换并不是与任意外部进程协作的跨文件事务。外部工具直接修改设备文件时应停止并发写入；最后一次校验之后发生的外部改写，不能仅靠哈希检查完全消除竞态。此限制不能写成“绝对原子恢复”或“任何并发改动都不会覆盖”。

## 二、工程预览与切换

工程预览的名称显示为“候选工程（尚未应用）”，分别列出包的导出来源和应用目标。包内文件、包外保留文件及两者合并后的选择列表分别保存。选择保留文件时，右侧明确说明该文件未由本包提供，应用后继续保留左侧现有内容。

完整工程实际进入 Apply 后，沿用原有强制正常关闭并重新启动机制；失败时也不能继续把旧运行时视为新配置的运行时。仅预览或进入 Apply 前被门禁拒绝，不算配置已经应用。

同一设备的任务更新继续按“保存草稿 → 检查 → 结束并关闭任务会话 → 安全断开 → 更新任务文件 → 重连并重新读取”执行。它不自动改成每次保存都重启 Host。

资源核查窗口的定时器只核对连接/会话/停止条件，不周期性发控制器 IO 命令。窗口失效后，旧异步采样不得重新写回当前显示，原人工确认不得用于新连接。仍保留输出有效时不释放资源的保守门禁；需要保持真空或夹紧的设备，须先有该设备批准的恢复规则。
