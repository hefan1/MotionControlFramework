# V1.8 设备准备与任务会话的沙盒验证

日期：2026-11-08。对照《运动控制框架现场交互与配置应用手册 V1.8》中的任务未读取显示、设备准备按需读取及 U01 验收，重点覆盖第 847、883、891—892 页相关场景。本记录不是整本手册或 24 轴设备的验收结论。

## 环境与范围

- Windows Sandbox 中通过正常入口运行本仓库 Release 版 `MotionControl.Host.Wpf.exe`，执行前核对进程路径、窗口标题及复制文件 SHA-256。隔离工作树构建的验证版本哈希为 `2C7379F48D93C1872B528505CC48A171CE558EA71DB287FD196B3FD41ABCE09D`；合入主工作区重新构建后再次验收的 Host 哈希为 `7D4D525AE0BE684E301B391E866A4A6F39CF3E6964CAC377C1B7FB1FC71305BB`。
- Host 使用隔离的 Machine01 配置，通过 Virtual 适配器连接独立软件控制器 `MotionControl.VirtualController`，TCP 端口 19580、协议版本 2。界面操作使用沙盒窗口的 UI Automation，不操作宿主机鼠标。
- 测试配置的设备定义为 `WeldingExample`，执行入口为 `TaskEngine`；任务准备文件定义一项“十三轴设备准备”。控制器 API 实际读取 13 轴和 14 个映射输出。
- 原配置种子未修改；各次 Host 使用单独的沙盒本地配置目录。测试结果、前后截图和基线/中间/最终配置副本保留在主机忽略目录 `tmp/v18-sandbox-20261108/results/`。

## 发现并处理

1. **正式画面复现：任务未读取却展示 C# 准备行。** 准备页显示“焊接工位”“压合工位”及 0/2，同时又提示没有已发布的任务准备会话；总览同时显示任务尚未读取与会话身份未确认。`baseline-preparation.png` 和 `baseline-overview.png` 保留原现象。
   - 保留 C# 和任务列表两份准备定义；任务入口只展示当前连接、当前发布会话及配置代次均可确认的准备快照。未知、异常、断线或代次变化时清除旧行和选择，保留异常诊断，不将未知标记为“未配置”。
   - 总览仅在状态提供器明确为未读取且前后身份采样均为空时显示未读取；状态与身份矛盾、读取失败或采样变化时继续显示未知，不能定位旧工位。重新读取后同 ID 工位仍需重新选择。
2. **准备范围切换与并发收尾。** 通过内存设备受控复现任务准备安装通知期间被其他配置替换、同 ID 配置在提交期间替换、关闭失败或并发关闭等情况；这些不是本轮实际误运动。
   - 任务会话绑定实际安装的准备代次；安装过程中被替换则拒绝发布，关闭时不覆盖其他代次。并发关闭共同等待同一次 Host 收尾，不同退出交接方式冲突时要求等待并重试。
   - 操作员已看到的“全部/所选”准备范围均绑定点击时的连接、入口、配置和观察代次，在 Runtime 命令锁内复核。只有尚未确认范围的任务入口“全部工位回零”继续支持先按需读取再提交，原有急停、轴、报警和恢复门禁不变。
3. **失联与准备停止记录。** 在内存测试中控制取消回调，让准备任务先退出、停止收尾仍未完成，然后作废连接；修复前可错误保存安全结束记录，修复后拒绝确认并保留准备占用及记录。Host 锁存失联时作废旧连接标识和准备记录复用资格；运行时停止收尾核对原连接，已确认失效的会话不能被当成当前任务准备会话。
4. **既有回归检查期望过时。** 在未修改的基线 `5ef368f` 和修复版本中均复现“断卡失败后现场按钮检查”失败：旧测试期望在连接标识已作废后直接复位。检查现改为确认按钮监控恢复、失效连接拒绝复位，正常断开并重连后再通过新上升沿复位；未放宽运行时门禁。

## 验证结果

- 修复前回归分别复现主表错误、会话身份矛盾、准备配置替换、关闭失败、并发关闭、范围切换及停止收尾失联问题；修复后沙盒操作页面内部检查 **55 组通过**，设备准备内部检查 **19 组通过**。
- 沙盒中的任务准备检查、任务设备检查以及 `--runtime-regression` 均通过；相关 Release 构建 0 警告、0 错误。任务准备检查首次因沙盒没有共享样例目录而失败，补齐只读样例路径后通过，不把环境失败记作产品通过。
- 主工作区重新构建的正式 Host：任务未读取时总览提示一致、准备页为空且显示范围待确认；直接点击“全部工位回零”后按需读取任务，准备页显示唯一的“十三轴设备准备”，并因 `Feeder_Z` 未使能明确拒绝。截图为 `main-overview.png`、`main-preparation-unloaded.png`、`main-preparation-interlock.png`。
- 命令前后软件控制器 API 显示 13 轴均未使能、停稳且位置不变，14 个映射输出均非激活。Host 正常关闭后再次读取同样状态，保留最终隔离配置，再通过独立控制台正常关闭软件控制器；主工作区产物的收尾结果见 `guest-main-finished.json`。

## 待继续验证和处理

- 本轮没有验证使能后的真实回零、完整生产循环、实体控制卡或现场安全回路，也没有完成 V1.8 的 24 轴及 24→6→24 项目切换验收。多轴组合等尚未支持的动作不能绕过现有联锁声称通过。
- 以下为代码审查提出的通用后端风险，尚未在本轮 Virtual 后端复现：失联时已进入发放边界的任务命令应作为在途/结果未知处理；部分 C# 流程持有原始轴和 IO 对象，需要验证通用控制卡反馈自行恢复时旧步骤不会继续发新动作；任务资源日志清理及暂停/退出快照保存还需验证失联时保留原证据。Virtual 后端自身锁存断连，不能据此声称它会自动恢复。
- 准备停止记录在调用安全结束保存前会检查原连接，但该检查与底层文件保存尚不是一个可中断的事务。下一轮需使用受控持久化延迟复现失联与写盘交错，并设计提交门禁，避免把当前检查扩展成未经验证的全局断线安全结论。
