# Host 退出设备协调实施计划

> 执行：executing-plans，在独立分支直接实施；不合并主线。

**目标：** 专用任务退出和普通关闭使用同一个未完成会话判断；App 的退出过程固定原设备上下文，关窗事件不再直接编排设备停止、输出检查及恢复保存。
**架构：** 在现有 Host 项目新增具体 HostShutdownOperation，保存原 Runtime、连接服务、任务入口与恢复服务；只协调本次退出。界面确认、工程门、断卡通知和失败提示仍由 App 负责。不建立通用生命周期框架。
**技术：** C# / .NET Framework 4.8 / WPF；Windows CI；中文注释。
**设计依据：** 用户确认的职责归位方向，以及前批 docs/verification/2026-11-10-task-session-lifecycle-closure.md 未关闭事项。

## 本次裁定

先完成退出这一条可独立验收的链，不同时大改启动、连接装配和逐卡多品牌；避免多个高风险生命周期修改互相遮蔽。HostShutdownOperation 是组合层具体类，只使用现有类型；原连接核对使用一个有明确名称的校验回调，不引入回调管线。
本机容器不能解析 GitHub 域名、无 dotnet/Windows。使用已连接 GitHub 与独立 Windows 工作区执行；临时迁移脚本/工作流最终删除。独立分支写入和草稿 PR 沿用用户已授权的仓库工作方式，不强推或合并。

补充裁定：把已经通过测试的四个退出事件/工程门方法和五个退出字段原样移至 App.Shutdown.cs。partial 只按职责整理同一个 App 的物理文件，不新增执行层次；真正的设备操作职责仍属于 HostShutdownOperation。增加结构红绿检查和方法体逐字比对，避免把改名当作行为重构。

## 验证重点

1. 专用软件退出入口必须识别尚未发布的后台读取，等到同一读取及持权清理结束。
2. 原关闭失败后，退出重试应继续同一种关闭交接，不通过已撤销的操作入口重新发 Abort。
3. 关机门禁等待期间 App 换上下文，旧操作拒绝继续；失败取消只影响原 Runtime，不解除新 Runtime 的退出保护。
4. 保存恢复记录必须在停止和输出核查完成之后；无法确认连接或保存服务时明确失败。
5. 未完成装载和关闭须纳入 App 正常关窗、强制退出告警和报警连续性记录的判断。
