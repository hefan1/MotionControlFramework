## 新增 21 组执行检查

| 检查 | 观察结果 |
|---|---|
| 顺序、示教与变量目标 | 赋值在先，X/Y 到指定内存终点后才执行末尾输出 |
| 条件与业务 NG | NG 进入不满足分支；All/Any/Not、六种比较符合定义 |
| 八种变量类型 | 各类型赋值/比较通过；uint 到 double 不截断；带时区日期按同一时刻比较，混用时区拒绝 |
| 未知数据等待 | 未注入的 DI 不等于 OFF；变量无效时等待并显示名称 |
| 无效分支 | 不猜测 false 分支，明确保留失败节点 |
| 并行汇合 | 两个分支同时等待；一个完成时主任务仍不进入后续动作 |
| 独立轴 | 两根逻辑轴同时保持内存运动状态 |
| 并行故障 | 一个分支缺少有效值后，兄弟轴取消并释放占用；末尾输出不执行 |
| 叶节点和父级超时 | 超时定位到对应节点，父级时限包括子动作，保留失败前等待对象 |
| 相对运动暂停恢复 | 位置与活动计时冻结；修改目标变量后恢复仍到原终点，只接受一次动作 |
| 暂停与延时 | 暂停超过时限也不消耗活动预算；恢复完成剩余延时 |
| 暂停期间取消 | 不用恢复即可取消，终态后轴不再变动且不写后续输出 |
| 取消竞态 | 15 轮预取消/立即暂停取消，加外部运行中取消及 10 轮并发暂停/恢复/取消，均收尾 |
| 同轴冲突 | 同组争用失败并清理；独立运行争用失败不能释放另一个运行的轴 |
| 运动前置条件 | 未使能、未回零、报警均拒绝接受动作 |
| 动态检查 | 无效变量、变量超限、相对终点越界和运动中报警均被拦截 |
| 内存回零与停止 | 回零完成置参考有效；中断不置成功；停止节点不能夺取其他动作控制权 |
| 子任务与冻结 | 两次调用产生不同编号；修改原定义及子任务不影响已启动的运行 |
| 不支持能力 | ResourceScope 和 CoordinatedMove 在任何动作前拒绝，包括未选分支 |
| 运行与快照隔离 | 不同内存设备/运行不串值，旧快照不被后台改写，终态不接受控制请求 |
| 展开规模 | 无环但指数调用的定义到 10000 次节点调用时明确失败并退出 |

`ExecutionChecks*.cs` 按流程、数据、控制、运动和测试组织分文件。检查失败时仍取消本组创建的所有运行，并等待收尾；文件保存回归继续只使用既有测试专属临时目录。

## 本轮复查中修正的事项

- 测试最初使用不存在的停止枚举，经读取现有 `AxisStopMode` 后改用 `Controlled`，没有修改公共契约。
- DateTime 不能直接比较不同 Kind 的本地时钟字段：有时区的值统一按 UTC，缺少时区的一侧明确报错，并补充回归。
- 每次节点调用异步让出执行权，避免大量即时子任务累积同步调用栈；加入总展开量检查。
- 失败快照保留之前等待的具体 DI、变量或轴信息，避免只留下“超时”而丢失定位线索。

## 验证边界

- 没有新增外部依赖，没有修改 Host、原有 Runtime 流程、厂商 API 或实际设备配置。
- 执行前后程序集检查均未发现 WPF、Host 或厂商适配器依赖；检查输出目录没有正运动/雷赛原生 DLL。新增执行源码没有原生 API 调用。
- 本轮为**纯软件内存仿真**，不是 ZDevelop/ZSimu 控制器验证。ConfigureAxis、DO、回零等只改变本检查进程中的状态。
- 单轴使用匀速进度模型，不模拟加减速、伺服动力学、传感器或厂商回零模式；多轴插补尚未实现。
- 同轴争用只做即时拒绝；完整轴/区域资源仲裁、退出确认、死锁处理留到阶段 3。
- 当前暂停保留内存执行点；跨进程恢复、工件周期关联、变量新鲜度、UI 运行监控和真实停止确认仍需后续实现验证。
