# V1.8 UI-04：任务会话来源修复与沙盒验证

## 原因和改动

交接 PDF 的 UI-04 指出，读取设备流程后，页面缺少可核对的任务会话标识、加载时刻和执行任务版本。任务配置页的文件快照也不能证明它就是当前执行会话。

- `TaskMonitorSession` 在构造执行器时保存同源的设备任务清单修订和各任务修订；`TaskMonitorLauncher.LoadTaskSessionAsync` 确认连接与准备配置后发布唯一任务会话标识和 UTC 时刻。该标识不等于控制器连接会话号。未提供工程整体版本时明确写“工程版本未提供”。
- 任务配置页、工位运行页和步骤引用详情展示同一有效会话；来源详情区展示清单修订与任务修订。保存文件不等于载入运行会话。
- 连接失效、准备定义换代、任务控制权变化或关闭进行中，旧会话不再标为当前有效。快照读取同时失败时清除旧来源；关联按钮在点击时重新检查身份。诊断内容限制高度并可滚动。
- `TaskSessionMetadataChecks`、`BoundTaskLoadChecks` 使用隔离内存设备和故障注入检查发布、重读、关闭失败、准备版本变化及来源显示，不向设备发送运动命令。

## 验证结果

2026-11-09 使用 Windows Sandbox，软件控制器和正式 `MotionControl.Host.Wpf.exe`，项目为沙盒独立副本 `V18UiAuditProject/Machine01`。未占用本机鼠标。正式程序来自工作区 Release 构建，软件控制器来自同一构建目录。

- 任务编辑检查：26 组、失败 0；操作员页面检查：63 组、失败 0。包含连接中断、重连、准备配置换代、控制权变化、关闭失败/等待和快照故障的内存场景。
- 正式 Host 页面读取设备流程后，工位运行与任务配置均显示会话 `73d17a16-c8f2-4588-b95a-e08874b13cbe`、19 个任务快照和“工程版本未提供”；来源详情显示设备任务清单 R1 及各任务修订。
- 在未启动生产的沙盒会话中关闭任务后，工程诊断显示“当前没有可确认的任务会话”；重新读取生成 `5048538a-22f0-4e33-8d9e-387227b880b6`，与旧编号不同。
