# V1.8 当前报警页对照与沙盒验证

## 改动与边界

依据《运动控制框架_现场交互与配置应用手册_V1.8_源码对照与24轴应用_20261107.pdf》第 727 页，调整正式 Host 的当前报警页。手册的夹具报警和反馈值是示意，不作为设备实际数据。

- 有报警时宽屏并列显示报警列表和所选记录的检查、恢复指导；窄屏上下排列，处理指导可滚动，查看入口固定可见。筛选无匹配时收起旧详情并保持总记录数，清除筛选可恢复选择。
- 显示“软件报警记录”和记录条件，说明其不代表实时输入；零条只表示报警服务无记录，不代表现场无报警。没有 Runtime 或连接周期未确认时明确显示来源未提供或现场状态未知，不使用旧工位步骤。
- 现有报警记录不含连接周期及可验证的工位、输入归属，因此查看工位运行、IO 监控、轴手动只打开页面，不自动定位；点击时重核连接周期。目标页面可能保留之前的选择或高亮，Host 在页面说明中提示人员重新核对；切换语言、重选同页或同一导航分类时提示仍保留。记录原有的关联输入仍可在报警指导和诊断中查看。
- 断连时保留当前 Runtime 可读到的报警记录并标为状态未知；如果 Host 移除了 Runtime，则显示来源未提供，不虚构记录。非停机提醒在收到恢复上报后才能自动清除，不能只依据现场条件推断已清除。
- 未改动已验收的轴映射、IO 映射、轴手动和 IO 监控页面，也未改变顶部、左导航或底栏布局。恢复精确定向需要来源端提供经验证的连接周期和对象身份，不能由页面按名称或时间猜测。

## 沙盒验证

- 使用正式 Host、独立软件控制器和隔离十三轴配置。软件控制器接口确认十三轴停止、十四个映射输出不活动；核对急停输入 DI3 原值为低，按测试接口置高后在正式界面尝试复位，系统因停机条件仍有效而拒绝，产生真实的软件停机报警。随后将 DI3 恢复为原值，没有发送轴运动或输出写入命令。
- 修改前空态和有报警截图为 `49-current-alarms-baseline.png`、`50-current-alarms-active-baseline.png`；候选 Host 依据同一软件接口重新产生报警，宽屏、窄屏及筛选截图为 `54-alarm-candidate2-active.png`、`56-alarm-candidate2-narrow.png`、`57-alarm-candidate2-filter.png`。报警计数与筛选数量独立，筛选和刷新不复位报警。
- 从报警页打开 IO 监控时只打开页面，实际界面显示未自动定位及旧高亮提示（`55-alarm-candidate2-io-warning.png`）；轴、IO 的验收页面未改动。内部回归覆盖提示在语言切换、同页重选和顶部分类重选后仍保留。
- 正常断开并重新连接同一个软件控制器，断开后正式 Host 将 Runtime 置空，报警页显示未读取状态；复核发现原来源行仍写设备运行数据，已修为“报警来源未提供，现场报警状态未知”。断开前后软件控制器状态、模拟输入原值和测试配置均保留在 `tmp/v18-station-ui-20261108/results/`。断连、同 Runtime 重连、连接周期失效与点击间隙的场景另由隔离内存 Runtime 回归覆盖。
- 解决方案 Release 构建为 0 警告、0 错误；操作页内部检查 63 组、0 失败，覆盖宽窄布局、筛选、断连、重连、来源未知与导航提示。内部测试和软件控制器的模拟状态均不代表真实设备或安全回路验收。

## 仍需验证

- 本轮没有执行真实生产循环、现场急停、安全回路、实机报警复位或复位后启动。窄屏受保护的顶部设备状态区域仍有裁切，需要在允许调整外壳时另行处理。
