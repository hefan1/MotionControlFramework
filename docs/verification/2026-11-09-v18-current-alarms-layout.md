## 改动与边界

依据《运动控制框架_现场交互与配置应用手册_V1.8_源码对照与24轴应用_20261107.pdf》第 727 页，调整正式 Host 的当前报警页。手册的夹具报警和反馈值是示意，不作为设备实际数据。

- 有报警时宽屏并列显示报警列表和所选记录的检查、恢复指导；窄屏上下排列，处理指导可滚动，查看入口固定可见。筛选无匹配时收起旧详情并保持总记录数，清除筛选可恢复选择。
- 显示“软件报警记录”和记录条件，说明其不代表实时输入；零条只表示报警服务无记录，不代表现场无报警。没有 Runtime 或连接周期未确认时明确显示来源未提供或现场状态未知，不使用旧工位步骤。
- 现有报警记录不含连接周期及可验证的工位、输入归属，因此查看工位运行、IO 监控、轴手动只打开页面，不自动定位；点击时重核连接周期。目标页面可能保留之前的选择或高亮，Host 在页面说明中提示人员重新核对；切换语言、重选同页或同一导航分类时提示仍保留。记录原有的关联输入仍可在报警指导和诊断中查看。
- 断连时保留当前 Runtime 可读到的报警记录并标为状态未知；如果 Host 移除了 Runtime，则显示来源未提供，不虚构记录。非停机提醒在收到恢复上报后才能自动清除，不能只依据现场条件推断已清除。
- 未改动已验收的轴映射、IO 映射、轴手动和 IO 监控页面，也未改变顶部、左导航或底栏布局。恢复精确定向需要来源端提供经验证的连接周期和对象身份，不能由页面按名称或时间猜测。

## 页面验收时记录的待解决项

- **本次页面验收时，跨连接的停机报警交接尚未解决。** 当时主工作区 Host 的真实沙盒操作中，急停停机报警已发生且没有执行成功的报警复位；正常断开再连接后，Host 重建 Runtime 和报警服务，页面显示新服务的 0 条软件记录、设备等待复位。`Runtime/AlarmHistory` 中仍可找到该次 `EMERGENCY_STOP` 发生记录（`alarm-main-journal-evidence.json`），但历史日志不等于当前锁存条件，也未证明复位或启动门禁保留了断开前的所有普通停机条件。本轮没有在重连后提交复位或启动。后续需设计并验证跨连接、异常断连及重启时的报警来源、锁存和恢复交接；不能把日志中的旧值直接冒充实时条件。
- 当时建议设计可可靠持久化的连接会话与未确认状态：异常断连、进程重启、记录损坏或来源尚未重新上报时维持未知及动作门禁；正常交接也要等待旧报警生产者和通知收尾。复位、准备、启动及可能运动的手动入口需要核查同一恢复结论，停止和必要保持动作不能被阻塞；缺失记录的首次部署与迁移须明确处理。若旧条件无法由当前来源确认，需要设备维护核查及记录，确认后仍不能自动启动。应先在沙盒覆盖普通非急停报警、多条件、写入中断、重连与重启，再考虑实机验收。
- 本轮没有执行真实生产循环、现场急停、安全回路、实机报警复位或复位后启动。窄屏受保护的顶部设备状态区域仍有裁切，需要在允许调整外壳时另行处理。
